# PROXIMA AI

Платформа для владельцев кабинетов Wildberries: каждое утро система сама собирает данные кабинета по официальному WB API, считает норму и показывает одну строку - «вчера N заказов против нормы M, отклонение x %». Дальше по лестнице - аномалии с ценой в рублях, гипотеза причины с проверкой, запись решения и сверка «сработало ли».

Два правила, которые объясняют почти всё в этом репозитории: **в WB только чтение** (любая запись - архитектурное нарушение) и **у каждой цифры есть источник** (артефакт ответа WB или детерминированный расчёт; LLM объясняет, но не считает).

## Что в этом репозитории

Код платформы:

| Каталог | Что это |
|---|---|
| `services/collector` | TypeScript-коллектор WB API (npm workspace `@proxima/collector`) |
| `services/control-plane` | Python control-plane (uv, 3.14): расчёты, норма, диагностика |
| `services/webapp` | Next.js веб-морда (сводка `/brief`) |
| `contracts/` | Канонические JSON Schema контракты (`signal`, `diagnosis`, `decision-record`) |
| `db/migrations/` | Ordered immutable миграции (additive-only, с self-checksum) |
| `infra/`, `tools/`, `scripts/` | Обвязка: systemd/compose, верификаторы, оркестрация |

Документация, планирование и операционные знания живут в **приватном companion-репозитории** `proxima-ai-ops` (у контрибьюторов подключается в рабочее дерево симлинками - см. «Композитное рабочее дерево» ниже).

## Лестница продукта

| Ступень | Что появляется |
|---|---|
| M-00 разведка API | факты по эндпоинтам, лимитам, глубине |
| M-01 сбор и хранение | дневной ряд кабинета копится сам, статус данных на экране |
| M-01b воронка фоном | воронка по товарам копится из v3 |
| M-02 база нормы | норма = медиана 14 полных дней |
| M-03 сводка | «вчера против нормы» каждое утро |
| M-04 аномалии | список по потерянной выручке в разрезе SKU и категории |
| M-05 план действий | гипотеза, проверка, решение, сверка исхода |

## Стек и запуск

Node.js 22 (collector, webapp), Python 3.14 через uv (control-plane, tools), PostgreSQL 16.

```bash
npm ci                       # PUPPETEER_SKIP_DOWNLOAD=1, иначе тянет Chromium
uv sync --python 3.14 --project services/control-plane --extra test --locked
make verify                  # единый гейт: типы, тесты, контракты, миграции, границы, секреты, hygiene
```

`make verify` без локального PostgreSQL 16 печатает `pg-roundtrip: SKIP` и выходит с кодом 0 - миграции при этом не проверены. Документозависимые проверки (архитектурные карты, бюджеты WB API) выполняются, когда рядом лежит `docs/` из ops-репозитория; в CI на публичном репо они пропускаются.

## Композитное рабочее дерево

Разработка идёт в композите: публичный чекаут кода + sibling-чекаут `proxima-ai-ops` (документация), связанные симлинками.

```bash
bash scripts/agent/workspace-links.sh   # идемпотентно расставляет симлинки на ../proxima-ai-ops
```

Приватные пути (`docs/`, `_bmad*/`, `STATE.md`, `DECISIONS.md` и др.) навсегда закрыты в `.gitignore` публичного репо - воркер физически не может их закоммитить. Гард-рейл `make hygiene` падает на боевых IP, именах кабинетов и внутренних хостов.

## Как здесь работают

Одна единица работы = одна ветка + один PR + один результат, который заказчик проверяет одним действием. Пишет либо конвейер ИИ-агентов (OpenHands под надзором), либо человек - по одним и тем же правилам: `make verify` зелёный, независимое ревью, мерж делает владелец проекта. Правила для человека - `CONTRIBUTING.md`. Сервер только на чтение; деплой - по явной команде с записанным планом отката.

Правила для агентов и контрибьюторов: `AGENTS.md` (публичная версия; полная рабочая - в ops-репозитории).
