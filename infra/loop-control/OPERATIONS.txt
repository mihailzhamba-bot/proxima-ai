Новый управляющий VPS

Paperclip работает как UID 1000, Hermes UID 10000, Bridge/Telegram UID 10001. PostgreSQL

выдаёт оператор отдельно; генератор не создаёт авторизацию во внешних сервисах.

Compose задаёт отдельные лимиты памяти/CPU/PIDs: PostgreSQL 1GiB/0.5/128,
Paperclip 2GiB/1.5/256, Hermes 2GiB/1/128, Bridge 256MiB/0.5/64,
Telegram 128MiB/0.25/32. Все Docker logs ротируются: local, 10MB x3.

Проверка кандидата и публикация
Порядок: prepare, immutable verify, immutable build, independent review,
begin-publication, gated push, finish-publication. Кандидат проверяется по blob каждого
tracked-файла и точному SHA; source и .git монтируются read-only. Изменения защищённых
tests/config/контрактов в worker-кандидате запрещены. Mountpoints создаются заранее;
tracked coverage, symlink, выход за checkout и неожиданные файлы отклоняются.

Producer использует только доверенные /opt/offline/npm и /opt/offline/uv, копирует их
в writable /tmp и явно запрещает сеть/download Python. CI=true включает существующий puppeteer.ci.json для Chromium внутри изоляции Docker;
NEXT_TELEMETRY_DISABLED=1 запрещает telemetry сборки. Python 3.14 заранее установлен
в verification image. HOME - scratch; USER/LOGNAME берутся из фактического UID.
Prepare устанавливает locked dependencies, затем package-файлы становятся read-only.
Отдельно доступны writable build outputs, .vite-temp/.vite caches и build-only overlay
next-env.d.ts. PROXIMA_VERIFY_READONLY включает сравнение codegen без записи исходников.
make verify обязан пройти настоящий pg-roundtrip: PASS. Логи и SHA-bound receipts
сохраняются вне candidate mounts в приватном evidence directory с редактированием секретов.

Push запускается через доверенный Python -I -S wrapper. Родитель сохраняет PID/start,
PGID/SID/boot ID и release intent с fsync до отправки разрешающего байта. Если родитель
падает раньше, EOF запрещает exec. Дочерний процесс начинает новую session; recovery
проверяет всех её живых участников, включая SSH/helper после смерти лидера Git.
GIT_SSH_COMMAND отключает ControlMaster/ControlPersist. Timeout сигналит owned group;
оставшийся участник session не даёт подтвердить остановку.

Управление и восстановление
loopctl.py поддерживает status/wake/pause/resume/stop/events/recover-pr и явную сверку.
Wake идёт через Paperclip. Повтор и потеря ответа не создают вторую работу.
Неопределённый dispatch не повторяется даже после истечения 24h native idempotency Hermes.
Оператор сверяет remote run list и принимает подтверждённый external ID.
Hermes после restart переводит незавершённый run в interrupted; SSE не имеет replay,
поэтому состояние читается polling. Cursor событий Paperclip хранится постоянно.

Pause сохраняет queued job и уже выданный publication permit для продолжения после
resume. Отмена немедленно меняет generation и запрещает новые публикации. Paperclip
cancel требует Board и сам не останавливает Hermes: Bridge отдельно останавливает
Hermes и ставит OpenHands на паузу, затем проверяет их состояния. Пока подтверждения
нет или publisher может работать, отображается CANCELLING, а не подтверждённая остановка.
Поздний child отменённого parent не получает lease. Подтверждённо отозванный или аварийно завершённый
parent переводит ещё не отправленную работу в quarantine.

Потерянный worker receipt: /usr/bin/python3 -I /opt/loop/loopctl.py --config <operator-config>
recover-worker --id <job> --input-file <receipt>
проверяет известный OpenHands CID и продолжает сбор bundle без второго dispatch.
Проверки ancestry/SHA/paths остаются обязательными. Перед публикацией повторно читается
Paperclip, включая отмену напрямую в upstream.

Потерянный push: runner.py --config <file> --recover-push <private publisher.json>.
Journal evidence/<job>/<attempt>/publisher.json имеет mode0600 и содержит permit;
не включать его содержимое в логи, prompts или PR. Живой процесс/session запрещает
settlement. Старый неполный journal без доказательства no-exec остаётся UNKNOWN.
Finished journal повторяет сохранённый receipt; умерший незавершённый publisher
фиксирует unknown outcome, после чего нужна внешняя сверка.

Оператор: loopctl.py --config <file> settle-publication --id <job>
--evidence-ref <inspection reference>. Проверяются destination branch SHA и все
подходящие PR. Эта операция не создаёт PR, не повторяет push и не удаляет branch.
Иной SHA или недоступная проверка оставляют permit активным. recover-pr принимает
только существующий PR с точным SHA и также требует доказанной остановки publisher.

Telegram и модели

известный 503 до dispatch. Vendor5xx остаётся неопределённым исходом.

факта не получают полный grounding score. Пустой config не запускает оценивание.

Backup, rollback и приёмка
Перед deploy сохранить mode0600 зашифрованные backups PostgreSQL, Bridge SQLite,
отдельного Hermes state и Paperclip storage. SQLite копируется через backup API,
не cp работающего файла; Bridge использует DELETE journal. Перед rollback прекратить
новый dispatch, остановить активные попытки и сохранить unknown intents. Восстановить
совместимые версии/schema в отдельном volume; проверить integrity и число записей.
Не удалять решения и uncertain runs ради разблокировки очереди.

Установить backup.py и health.py как /usr/local/sbin/loop-backup и loop-health,
затем loop-backup.service/.timer и loop-health.service/.timer. Backup идёт ежедневно
в 00:30 UTC с jitter, health - каждые 5 минут. Шифрование использует отдельный
/etc/loop/secrets/backup_encryption; ключ не входит в архив. Обязательны native
pg_dump, online backup всех Bridge/Hermes SQLite, Paperclip master/decision keys,
Hermes OAuth и idempotency state. Последний архив проверяется HMAC, расшифровкой и
restore в отдельном volume; копия архива и ключа хранится вне VPS.

На LOOP-control установить loop-egress-tunnel.service, loop-egress-proxy.service
и tinyproxy.conf. Создать отдельных loop-tunnel/loop-proxy, mode0600 tunnel key,
pinned known_hosts для home.main :65022 и включить оба unit. tinyproxy 1.11.1
слушает только gateway 172.30.240.1 и принимает только Hermes 172.30.240.2.

Hermes подключается только к internal loop-hermes-private и выходит к OpenAI через
loop-egress-tunnel.service + loop-egress-proxy.service. OpenHands доступен Bridge
как localhost:18000 через loop-openhands-tunnel.service и relay в namespace Bridge.
Туннельный SSH user разрешает только local forward к Claudette 127.0.0.1:18002;
shell, SFTP и reverse forwarding запрещены. Установить network_preflight.py как
/usr/local/sbin/loop-network-preflight и включить loop-network-preflight.service.
Он создаёт отсутствующие internal сети только с точными subnet/gateway и блокирует
старт при drift существующей сети. Контейнеры имеют restart=no; Compose работает
foreground через loop-control.service и повторяет preflight в ExecStartPre при каждом
restart/reboot. Остановка tunnel должна давать отказ без прямого fallback.

Выполнение задачи подтверждает сотрудник с evidence. Mike отдельно сверяет эффект

http://127.0.0.1:18771. Direct public Bridge access is not required.
Existing verifier /home/verifier and /bin/bash are preserved; the LOOP unit sets
HOME=/var/lib/loop-runner and ProtectHome=yes. Historical verification trees are
not migrated or cleaned. Installer probes Docker, exact image offline caches,
Bridge auth, worker forced SSH and GitHub dry-run push as verifier, not root.
Manual review gate: /opt/loop-review/review-candidate requires a separate root-owned
/etc/loop-review/receipts/<head-sha>.json with base_sha, sha, diff_sha256, status=pass,

Native Hermes Telegram (15.09.2026)
===================================

Local incoming voice: configure_local_stt.py --assets IMMUTABLE_ASSET_DIRECTORY
adds offline faster-whisper STT to this same isolated Hermes only. Install Linux
CPython 3.12 wheels at the versions pinned in local-stt.lock.json, place the
model and model-manifest.json alongside python-deps, and verify transfer hashes
before configuring. No compilation or runtime model download is required.
The multilingual base model runs on CPU/int8; OMP_NUM_THREADS=2 and the existing
container CPU/memory limits remain in force. The model unloads after 60 seconds
idle. This config does not enable TTS, microphone capture, cloud STT, or the queue.
Native STT enriches voice text after command dispatch; a spoken /loop_confirm
does not become an owner control command. Validate through the real
tools.transcription_tools.transcribe_audio(file_path, source='gateway'), then
through a new owner voice message. Configuration/decoded audio are not proof of
an intelligible transcript or a delivered Telegram answer.

Native conversation uses the existing Hermes home/OAuth and separate Telegram
session routing. Do not start tools/loop/telegram.py for the same bot: exactly
one Telegram poller owns its updates. API-session MCP tools stay configured as
before; Telegram uses [loop_chat, no_mcp]. The no_mcp sentinel is mandatory to
prevent global MCP servers from being appended to the chat tool surface.

Runtime extension:
- tools/loop/native_plugin.py is a read-only Hermes user plugin (loop-chat).
- native_startup.py is a native gateway:startup hook. Plugin register() must be
  synchronous and cannot assume an asyncio loop; notifier starts via the pinned
  gateway _spawn_supervised coroutine factory after adapters connect.
- Native tools are loop_get_status and loop_prepare_action. They hold only the
  chat credential. Trusted Telegram pre-dispatch handles /loop_status,
  /loop_review DRAFT_ID, /loop_confirm DRAFT_ID, /loop_stop RUN_ID with a separate
  ingress credential; sender AND private chat must match the configured owner.
- Model drafts never launch work. The trusted preview includes the actual fixed
  edit, expected result, base SHA and paths. Confirm requires a nonce-bound
  successful Telegram message receipt; preview expires after 15 minutes.
- Confirmed requests enter Paperclip. Bridge fences job_id/template/fingerprint
  against the owner confirmation and requires an acknowledged Paperclip parent.
  An unknown dispatch is reconciled, never blindly resubmitted.

Bridge API additions (all private; no public listener):
chat credential: GET /v1/chat/status, POST /v1/chat/drafts {template}.
native_ingress credential: POST /v1/native/preview, /preview-receipt, /confirm,
/stop; GET /v1/native/notifications; POST notifications/{id}/claim or /settle.
Native mutations validate user_id/chat_id/chat_type from the trusted ingress;
these fields are never accepted from model tool arguments. Notifications are
claimed durably before delivery. A lost acknowledgement is delivery_unknown,
not an automatic resend; /loop_status remains the recovery view.

Install on the existing dedicated control host only:
python3 infra/loop-control/configure_native_telegram.py --source CHECKOUT
This prepares a disabled-owner configuration and private rollback snapshot.
Activation additionally requires --user-id NUMERIC_ID --token-file PRIVATE_FILE.
The bot token must come from a new dedicated bot and a mode-0600 file. It is read
by native_gateway.py at process startup, never placed in Docker environment
inspection, command arguments, source, logs, or conversation text.

The installer preserves existing Compose limits/networks, Hermes API config and
model login. It installs read-only runtime overlays on the pinned images and
does not restart or change queue/Director pause. Validate Docker Compose, then
explicitly recreate only bridge and hermes (use --force-recreate because
replacing a bind-mounted file does not update the old container inode).
After changes to loop-egress PermitOpen, reconnect the SSH tunnel for the new
key restrictions to take effect. Permit only api.telegram.org:443 in addition
to the previously admitted model destinations; retain the private network.

Rollback: use /var/backups/loop-native/TIMESTAMP/configuration.tar.gz and its
receipt hash; restore the previous Compose/hermes/Bridge config and prior
overlay files, then recreate the same two services. SQLite snapshots accompany
the config backup, but do not restore an older DB over newer jobs merely to
roll back code. Newly created inactive files can remain in place. VPN SSH config
has its own /var/backups/loop-egress/telegram-TIMESTAMP snapshot; restore only
the dedicated LOOP account restrictions and validate sshd before reload.

Acceptance levels are distinct: code tests; installed plugin/role/network
smoke; a real owner Telegram conversation across restart; a confirmed task to
PR with its native result notification. Missing bot/owner credentials block
the last two. A healthy process or Telegram getMe response does not prove a
successful user conversation. Do not enable work merely to enable chat.
