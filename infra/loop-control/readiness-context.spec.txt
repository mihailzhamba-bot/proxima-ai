## Intent

Проблема: readPilotContext скрывает штатные insufficient и blocked вместе с payload. Director получает одинаковые brief:null и общую строку reason для неполной нормы, отсутствующей сводки и других причин. Теряются день сводки и фактический прогресс календарного окна. Это противоречит видимости пропущенных дней в SPEC CAP-4.

Подход: добавить объект readiness с ограниченными метаданными из уже прочитанных строк. Неготовый brief по-прежнему null. Полный payload и прежние поля ответа для готовой сводки сохраняются. Существующее наблюдение эффекта по свежему дню после горизонта не менять.

## Boundaries & Constraints

Всегда: изменить только services/webapp/src/lib/loop/context.ts. Использовать существующие status и brief, не добавлять SQL-запросов. Сохранить READ ONLY, set_config кабинета, авторизацию, пагинацию, сотрудников и content_boundary. Вы не один в репозитории: чужие правки не отменять. Все числа копировать из norm, не рассчитывать и не выдумывать.

Разрешено обычное инженерное решение в этом объёме; merge и production deploy требуют Mike.

Запрещено: менять service.ts, auth, миграции, тесты, зависимости, конфигурацию, сборщик, формулу нормы, правило дня эффекта. Не менять существующее условие fresh и прежнее поле reason. Не публиковать ветку самостоятельно.

Новый readiness имеет ровно поля:
- ready: существующее значение fresh.
- reason_code: null для fresh; иначе первый подходящий код по приоритету: data_status_missing (нет status), data_stale (stale не false), brief_missing (нет brief), day_mismatch (brief_day не last_full_day), norm_insufficient (status insufficient), brief_blocked (status blocked), brief_not_ready (другой не-ok статус), source_refs_missing (ok без источников).
- brief_status: ok, insufficient, blocked из строки brief; иначе null.
- brief_day: строка YYYY-MM-DD из brief.brief_day; при отсутствии или неверном формате null.
- norm_progress: только sample_days и window_days из brief.payload.norm, если оба целые числа, 0 <= sample_days <= window_days <= 366 и window_days > 0; иначе null. Не подставлять 14 при отсутствии значения.

## I/O & Edge-Case Matrix

| Сценарий | Вход | Ожидается |
|---|---|---|
| Готово | fresh status, ok, совпадающий день, SourceRef | ready true; reason_code null; brief сохранён целиком |
| Неполная норма | тот же день, insufficient, norm 9/14 | brief null; norm_insufficient; brief_day и 9/14 видны |
| Заблокировано | тот же день, blocked, norm null | brief null; brief_blocked; norm_progress null |
| Нет сводки | status свежий, brief отсутствует | brief_missing; brief_status/day/progress null |
| Нет статуса | status отсутствует | data_status_missing; brief скрыт |
| Устарело | stale true, существующий brief | data_stale; brief скрыт; день метаданных сохранён |
| Другой день | свежий status, brief_day отличается | day_mismatch; brief скрыт |
| Нет источников | status свежий, ok того же дня, source_refs [] | source_refs_missing; brief скрыт |
| Неверный прогресс | строки, отрицательное, sample>window или отсутствующее norm | norm_progress null; никаких выдуманных чисел |
| Приоритет | stale и insufficient одновременно | data_stale; brief_status insufficient сохранён |
| Изоляция | другой tenant/offset | существующая валидация, транзакция и привязка tenant сохранены |
