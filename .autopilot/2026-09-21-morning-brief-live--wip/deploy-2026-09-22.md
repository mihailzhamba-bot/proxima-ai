Порядок обратный развёртыванию (источник - runbook §7, release-m01.md @ d134138):

1. Таймеры: `systemctl disable --now proxima-morning@amirova-test.timer
   proxima-restore-check@amirova-test.timer`; rm drop-in
   `proxima-funnel-v3@.service.d/10-analytics-read-write.conf`; `daemon-reload`.
2. Прогоны релиза удалить целиком по `run_id` из `collector_runs`
   (`delete_run.py` в контейнере `control-plane` через `-v proxima_janitor_uri` + `-e
   JANITOR_DATABASE_URI_FILE`; всегда сначала `--dry-run`; удаление входного прогона снимает
   всё построенное на нём - AD-3).
3. Витрина: `docker compose -f infra/compose.yaml -f infra/webapp.staging.compose.yaml down`
   (без `-v`: том с данными остаётся; ручной `proxima-webapp-staging` не возвращается).
4. Код и окружение: `git checkout -- infra/jobs.env` → `git checkout v2026.09.0-baseline` →
   вернуть `.env` из `/var/backups/proxima/repo.env-v2026.09.0-baseline`.
5. Остаётся после отката (намеренно): переименованные токены, роли базы, `/srv/proxima-ai/raw`,
   `proxima-psql-owner`, миграции 007-018 применёнными (пустые таблицы лестницы не мешают).
