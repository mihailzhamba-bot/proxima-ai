## Дополнения

- 2026-08-27 — решения грилля (утверждены Mike выбором «Recommended» в каждой ветке):
  1. Скоуп: «Ядро детектора» — baseline 7/14/28 + сезонность + U×CVR×AOV декомпозиция + порог + ₽-фильтр ≤10/день + дедуп в control-plane; выход = внутренний типизированный контракт под consumed-surface (§5 аудита PA-39) и будущий signal.schema.json; PMM-21 = interface stub с safe default; PMM-29 binding = тонкий adapter отдельным follow-up; тесты на явно помеченных инжектированных кейсах; реальный backtest отложен документированно.
  2. Метрика: заказы — U = openCardCount (прокси трафика), CVR = ordersCount/openCardCount, AOV = ordersSumRub/ordersCount, продажи = ordersSumRub; выкупы в payload как контекст; точные имена колонок верифицировать по реальному payload, маппинг в одном реестре с fail-closed.
  3. Baseline: мультипликативный индекс дня недели (s_w = среднее дня недели за 28д / среднее все дни за 28д, окно без оценочного дня); Expected(D,W) = скользящее среднее за W дней × s_w(D); триггер = отклонение на окне 28 при корроборации хотя бы одним из 7/14; сигнал несёт все три дельты; дедуп = открытый сигнал не плодит новых до восстановления выше порога или cooldown 7 дней; история <21/28 дней → BLOCKED INSUFFICIENT_HISTORY.
  4. Декомпозиция: Шепли по трём множителям (среднее по 6 порядкам), вклады суммируются в дельту ₽ точно; ноль фактора = явный кейс «фактор схлопнулся, вклад 100%», не крэш и не NaN.
  5. Порог: значимость = revenue_delta = Expected(D) − Actual(D) за день (имя revenue_delta_orders, не DEC-003); топ-≤10 по убыванию с нижним порогом; дефолты: падение ≥20% против Expected(28) с корроборацией 7/14, floor = 3 000 ₽/день; оба в конфиге.
  6. Гранулярность: SKU (nmID) + кабинет; кабинет по «зрелой панели» (SKU ≥21/28 дней истории), исключённые в payload (panel_size, excluded_count); категории — W2; новые SKU на уровне SKU → BLOCKED INSUFFICIENT_HISTORY со счётчиком в observability.
  7. Граница: чистая функция от канонического входа (ноль БД/сети) + отдельный loader (резолв последних DOWNLOADED task_id за период, парсинг payload jsonb по реестру маппинга, fail-closed на отсутствующую колонку); день оценки D = вчера полный по Europe/Moscow, параметр для replay/backtest; snapshot_id = sha256 канонического JSON входного бандла (canonical_hash-паттерн) + source_refs на task_id; деньги в Decimal.
  8. «Мозг»: своё ядро производит полный DetectorResult (PROPOSED/BLOCKED + поля декомпозиции), типизированный 1:1 под минимальный набор PMM-29 (scenario_code=SCN-001, snapshot_id, source_refs, trust_marking=unreleased, ₽-дельта с method) + fingerprint = canonical_hash результата; импортный _run_scn_001 остаётся для adaptation-коммита PA-41/W2.
  9. Гейты: после зелёных тестов read-only smoke против staging через туннель (одна реальная строка payload, сверка реестра маппинга; туннель не поднят → UNKNOWN зафиксировать); Jira: PMM-20 → «В работе», комментарий с решениями грилля; DoD-аудит по чеклисту PMM-12 при закрытии рана.
