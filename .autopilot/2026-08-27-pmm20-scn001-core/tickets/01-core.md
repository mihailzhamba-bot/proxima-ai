## Что должно заработать

Чистая функция `detect()`: на вход канонический бандл дневных метрик по SKU (без БД и сети), конфиг порогов, источник порогов (protocol), состояние дедупа, дата оценки. На выход `Scn001RunResult`: сигналы PROPOSED (SKU + кабинет) с декомпозицией Шепли U×CVR×AOV в ₽, дельтами против сезонного Expected(7/14/28), revenue_delta_orders, dominant_factor, snapshot_id, fingerprint; BLOCKED-записи (INSUFFICIENT_HISTORY, INVALID_BASELINE, INVALID_INPUT) и счётчики (candidates, filtered_by_rub, dedup_suppressed, blocked_by_reason). Топ-≤10 по ₽-дельте. Бит-в-бит детерминизм на том же входе.

## Из брифа, дословно

> «baseline 7/14/28 с сезонностью дня недели» — «мультипликативный индекс… триггер = отклонение на окне 28 при корроборации хотя бы одним из 7/14; сигнал несёт все три дельты»
> «Шепли по трём множителям… вклады суммируются в дельту ₽ точно… Ноль фактора = явный кейс «фактор схлопнулся, вклад 100%», не крэш и не NaN»
> «топ-≤10 по убыванию с нижним порогом; дефолты: падение ≥20%…, floor = 3 000 ₽/день; оба в конфиге»
> «дедуп = открытый сигнал не плодит новых до восстановления выше порога или cooldown 7 дней»
> «кабинет по «зрелой панели» (SKU ≥21/28 дней истории), исключённые в payload»
> «snapshot_id = sha256 канонического JSON входного бандла (canonical_hash-паттерн)»
> «Деньги в Decimal»; «детерминированный расчёт (LLM запрещён)»; всё `unreleased`

## Критерии приёмки

- [ ] `detect()` на SYNTH-кейсе падения (−35% при живом трафике, CVR норм) → PROPOSED, dominant_factor = фактор с максимальным отрицательным вкладом, вклады суммируются в revenue_delta_orders точно (свойство проверено в тесте)
- [ ] SYNTH-кейс сезонных выходных (просадка сб/вс регулярна, оценка в вс) → НЕТ сигнала (FP-тест R01/AC PMM-20 №2)
- [ ] Корроборация: падение только против Expected(28), но 7/14 в норме → сигнала нет
- [ ] Дедуп: второй день того же падения → dedup_suppressed, без нового сигнала; восстановление «выше порога» открывает; cooldown 7 дней открывает заново
- [ ] ₽-фильтр: 15 кандидатов → топ-10 по revenue_delta_orders, counters.filtered_by_rub посчитан; floor 3000 отсекает мелочь
- [ ] Кабинет: распределённое падение по 30 SKU, каждое ниже floor → кабинетный сигнал по зрелой панели, panel_size/excluded_count в payload
- [ ] INSUFFICIENT_HISTORY (12/28 дней), INVALID_BASELINE (Expected=0), INVALID_INPUT (openCard=0 при orders>0) → BLOCKED-записи, счётчик blocked_by_reason, никакого NaN/деления на ноль
- [ ] Детерминизм: два прогона на одном бандле → идентичный результат, равные snapshot_id и run_fingerprint; порядок входных строк не влияет (сортировка внутри)
- [ ] `evaluation_date` параметризован; каждый сигнал несёт scenario_code="SCN-001", trust_marking="unreleased", source_refs (пусто на уровне ядра — заполнит loader), ₽-поле с method="revenue"
- [ ] `ThresholdSource` подменяется в тесте (паспорт-стаб): подменный источник даёт другие пороги → результат меняется соответственно
- [ ] Unit-тесты зелёные: `uv run pytest` в `services/control-plane`; ноль новых зависимостей в pyproject
