## Ответы грилля (утверждены Mike 2026-08-27)

1. **Q1 Стратегия:** Fixtures-first - строим PMM-5 сейчас на структурных fixtures (SCN-008 по форме scn_008_partial.json, SCN-001/005 - синтетические обезличенные), LLM за адаптером (mock в тестах, реальный провайдер после PMM-31). Схема diagnosis - черновик локально как вход для PMM-29. Не ждём блокеров.
2. **Q2 Схема:** Внутренняя draft - JSON-схема внутри control-plane (services/control-plane, рядом с кодом диагноза), помечена draft + указатель на PMM-29. Валидация Python-side (jsonschema). Не трогаем contracts/ (bot lane).
3. **Q3 LLM:** Адаптер + конфиг - интерфейс LLMClient (prompt + input → JSON по схеме) + mock-провайдер для CI/тестов + провайдер из конфига (env: имя модели, base_url, ключ - вне кода). PMM-31 позже заполняет конфиг.
4. **Q4 Размещение:** CP-субпакет - services/control-plane/src/proxima_control_plane/diagnosis/ (adapters/, prompts/, schema/, service.py, cli.py, батч-запуск). LLM-SDK в optional extra. Не задеваем future verbatim-дерево proxima/ (PA-41). Вызов - библиотека + CLI для PMM-32.
5. **Q5 Вход:** Envelope-минимум - DiagnosisInput = {scenario_id, generated_at, trust: "unreleased", payload, context_extracts, source_refs}. payload пер-сценарный: SCN-008 = форма scn_008_partial.json (сольется с PA-41), SCN-001 = синтетика с декомпозицией U×CVR×AOV, SCN-005 = OOS/days-cover поля. Маппинг на PMM-29 - adaptation-слой потом.
6. **Q6 Output:** Schema-enforce + retry - JSON Schema провайдеру (tool use / response_format где доступен), выход строго валидируется jsonschema, при невалидном - retry до 2 раз, потом fail-closed (диагноз не выдаётся). Mock возвращает валидный JSON. Системный промпт: числа только из входа, каждый факт с SourceRef, текстовые поля входа в ограничителях DATA (anti-injection).
7. **Q7 Eval:** Свои ≥12 кейсов на envelope-fixtures: по 3-4 на SCN-001 (включая кейс с декомпозицией U×CVR×AOV), SCN-005 (alternatives ≥2, unknowns ≥1), SCN-008 + 1 adversarial-инъекция + 1 кейс «числа Z нет во входе». Критерии автопроверки детерминированные: schema-valid, все числа output ∈ input, каждый факт с source_ref. Формат датасета расширяемый для PMM-33.
8. **Q8 Бюджеты:** Отложить в PMM-31 (механизмы бюджетов).
9. **Q8а Граница:** Флаг+аудит здесь - остаётся: flag llm_enabled в конфиге (rollback §16, деградация к детерминированному сигналу), per-signal timeout, JSONL-аудит вызова (ts, signal_id, sha256(input), model, prompt_version, outcome). Уезжает в PMM-31: дневной token-лимит/кабинет и enforcement.
10. **Q10 Процесс:** Автомат + PR - бриф в exec-plan + Jira PMM-5 (статус «В работе»), затем autopilot: ветка pmm-5-llm-analyst, implementation + eval + make verify (uv pytest, verify-стек) + reviewer subagent по завершении + PR. Демо на ретро - прогон CLI на eval-датасете с mock-LLM.
