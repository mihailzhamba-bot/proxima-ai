# Спецификация: Редизайн веб-кабинета Proxima — Warm Precision (PA-49)

## Задача

Mike строит платформу Proxima и делает много работы, которую не видит: «очень слабо выглядит», «хочется чего-то более погружённого и продуманного», «каждый день прийти посмотреть». Текущий каркас веб-кабинета — дефолтный холодный шаблон с пустыми заглушками-карточками. Нужен интерфейс, который выглядит как продуманный инструмент (канон Warm Precision, DESIGN.md), читается за секунды, честно маркирует демо-данные и доступен каждый день не только с Mac mini.

## Решение

Веб-кабинет в каноне Warm Precision: тёплая бумажная палитра, Inter + IBM Plex Mono, плотный спокойный шелл (256px сайдбар с секциями), метрическая полоса из 5 карточек с честными бейджами «FX» на демо-цифрах, утренний бриф как редакционный экран с critical-строками, спроектированные empty/error-состояния вместо заглушек, обе темы (светлая/тёмная тёплая) с первого дня. Результат поднят на VPS как staging-контейнер за SSH-туннелем — открывается с любой машины Mike без домена. Полный публичный деплой с доменом остаётся за PA-49 сессией 2.

## Решения по реализации

- **Ресёрч референсов (выполнен до прогона, 2026-08-25)** — выводы живут в утверждённом брифе и `reference.md`; распределение заимствований по требованиям: Linear → R04 (36px-плотность, спокойная пластика) и R06; Stripe → R05 (метрическая полоса: число+дельта+спарклайн, дисциплина «ничего лишнего сверху»); Grafana → принцип читаемости при плотности (R09-стайлгайд, дальше PA-52); Vercel → progressive disclosure (drill-down SourceRef — паттерн для PA-52, каркас не расширяет); Superhuman → R07 inbox как очередь решений; Triple Whale → Trust Layer «цифра всегда с источником» (в каркасе — бейдж FX как честная форма, SourceRef — PA-50+).
- **Анти-эталон (интервью №8)**: не SaaS-шаблон (сетка одинаковых карточек, градиенты, графики ради красоты) и не «госуслуги» (канцелярит в текстах, перегруженные таблицы). Тексты UI — простые человеческие формулировки; polish-круг сверяет в обе стороны.

- **Палитра light**: canvas `#f7f4ef`, surface `#ffffff`, hairline/border `#e7e5e4`, secondary text `#57534e`, primary ink `#0f172a`, accent violet `#6d28d9` (hover — ink), статусы 700-step: green `#15803d`, red `#b91c1c`, yellow `#b45309`, info `#1d4ed8`; violet-container `#ddd6fe` для selection-состояний. Почему: DESIGN.md дословно.
- **Палитра dark (тёплая stone)**: canvas `#1c1917`, surface `#292524`, border `#44403c`, secondary text `#a8a29e`, text `#e7e5e4`, accent violet светлее — `#a78bfa` (контраст на тёмном), primary ink → `#f5f5f4`; статусы 300-step: green `#86efac`, red `#fca5a5`, yellow `#fcd34d`, info `#93c5fd`, с тёмным текстом на чипах `#1c1917`. Почему: тёплая гамма канона; AA-контраст чипов в обеих темах.
- **Шрифты**: `next/font/google` Inter (variable) + IBM Plex Mono, self-hosted сборкой; fallback system. Почему: DESIGN.md; self-host обязателен для VPS без внешних запросов в рантайме (скачивание только при docker build).
- **Радиусы/тени**: 4px контролы, 8px контейнеры; тени только транзиентные слои (dropdown). Разделители — 1px hairline. Почему: канон.
- **FX-бейдж**: компонент `FxBadge` — микро-бейдж «FX» (uppercase, 10px, muted-фон, mono), ставится рядом с каждым числом из fixtures. Почему: ответ интервью №2.
- **Метрическая полоса**: серверный компонент `MetricStrip` + `MetricCard` (число mono 28-32px, дельта со стрелкой и знаком, статичный SVG-спарклайн из массива точек провайдера). Данные из `fixtures/metrics.ts` (структурные обезличенные). Спарклайн — inline SVG path, без библиотек. Почему: без новых зависимостей (граница брифа).
- **Провайдер данных**: расширяет существующий `lib/fixtures/*` — единая точка «что показывать» (массивы точек для спарклайнов, дельты). UI не знает про «настоящесть»; бейдж FX вешается на уровне карточек. Почему: PA-50 подменит провайдера, UI не меняется.
- **Brief**: серверный компонент; критические строки — `SignalRow` (36px, GYR-полоса 3px слева, ₽ mono справа tabular-nums); вердикт-строка `BriefVerdict`. Unreleased-плашка компактнее: одна строка, 12px, без иконки-треугольника, «unreleased · fixtures (DEC-006)».
- **Empty-состояния**: `EmptyState` (иконка лаконичная + одно предложение + строка «оживает в PA-XX»). Inbox: плюс мини-схема workflow. Почему: anti-эталон «не пустые стены».
- **Крафт**: `Skeleton` (пульс, тона surface), `SectionError` (error-boundary per секция), `CountUp` (клиентский, 300-500ms, отключение по `prefers-reduced-motion`), focus-ring токен, `::selection` в globals.css. Motion: только count-up и skeleton-pulse, обе уважают reduced-motion; спарклайны статичные (интервью №7).
- **Staging (G01)**: на VPS собирается образ из Dockerfile (git bundle → checkout → docker build), контейнер `proxima-webapp-staging`, publish `127.0.0.1:3000:3000`, `restart: unless-stopped`, env: `WEBAPP_REQUIRE_AUTH=false` (fixtures, без БД и секретов). SSH-алиас `proxima-app` (`-L 3000:localhost:3000`) в `~/.ssh/config` Mike — инструкцией в отчёте, сам конфиг Mike не правлю без запроса... нет: алиас добавить могу только на машине Mike — делаю сам, это локальный конфиг, обратимо; предупреждаю в отчёте. Почему: ответ интервью №1; паттерн деплоя PA-13 (bundle + detached checkout).
- **Git**: вся работа на ветке `feat/pa-49-warm-precision` от текущего HEAD; в main не коммитим; стейджим только файлы прогона (services/webapp/**, DESIGN.md одна строка, .autopilot/**); `git add -A` запрещён.
- **DESIGN.md/Jira**: однострочная правка статуса (R11), комментарий PA-49 (R12) — финальный тикет.
- Существующие факты, которые соблюдааем: eslint пин 9.39.5; `**/.next/` в .gitignore; vitest-набор расширяется, не переписывается.

## Состояния (deep-проход, сводка)

| Экран | First run / Empty | Error |
|---|---|---|
| Brief | вердикт «Критичных нет» + дайджест | SectionError на секцию, экран жив |
| MetricStrip | карточка «нет данных» (muted) | то же |
| Inbox/Dashboard/Admin | Inbox: EmptyState с мини-схемой workflow; Dashboard: EmptyState (PA-52); Admin: каркас 6 статус-модулей (нейтральные индикаторы, PA-54 оживит) | SectionError |
| Styleguide | всегда контент (это эталон) | не применимо |

Wrong input: форм в прогоне нет (логин не трогаем). Interruption: SSR-ренер идемпотентен, повторное открытие не дублирует ничего. Growth: спарклайн рассчитан на 30-90 точек без деградации; строки брифа — список без виртуализации до ~50 строк (PA-50 решит глубже). Boundaries: доступ — без авторизации в fixtures-режиме только на loopback VPS; публичный доступ не открывается. Aftermath: результат — редизайн + staging; отката не требует (ветка).

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `tokens` (globals.css) | все CSS-переменные обеих тем, radius, selection, focus | классы-токены через CSS vars | конкретные hex (только здесь) |
| `lib/fixtures` | все демо-данные (метрики, сигналы, дельты, точки спарклайнов) | типизированные геттеры `getMetrics()`, `getBrief()` | форматы и структурные значения |
| `components/ui` | примитивы Button/Card/Badge/GyrBadge/FxBadge/Skeleton/EmptyState | React-компоненты | внутреннюю разметку |
| `components/metrics` | MetricStrip/MetricCard/Sparkline | `<MetricStrip/>` | расчёт path, деградацию на узких экранах |
| `components/brief` | SignalRow/BriefVerdict/Digest | `<BriefPage/>`-состав | верстку строк |
| `shell` | сайдбар, топбар-полоса, unreleased-плашка, свитчер кабинета | layout | активную навигацию (usePathname) |
| `staging` (инфра) | скрипт сборки/запуска на VPS | runbook-шаги в отчёте | детали VPS |

Швы для тестов (меньше — лучше): (1) `lib/fixtures` геттеры — форма данных стабильна; (2) `lib/gyr`/`lib/format` — уже существуют, расширяем FX-токенами. DOM-проверки — smoke через `next build` + ручной просмотр стайлгайда; E2E не заводим.
