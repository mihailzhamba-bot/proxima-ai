# Спецификация: Exit-критерии W1-среза (PMM-11)

## Задача

«Срез завершён» без определённых критериев = дрейф (PMM-11, WBS AIOS-DEL-006). Критерии должны быть сформулированы до исполнения W1 и утверждены Mike; тикет после утверждения становится чек-листом закрытия среза, где каждый критерий при закрытии имеет ссылку на артефакт (демо/ADR/замер/ретро).

## Решение

Живой документ среза `docs/exec-plans/active/w1-slice-exit-criteria.md`: финальная редакция 6 exit-критериев (после грилля 2026-08-27) в статусе **Draft — awaiting approval**, плюс чек-лист закрытия «критерий → статус → артефакт-ссылка». В Jira PMM-11 уходит комментарий-черновик с тем же текстом для утверждения. Утверждает только Mike; после его «утверждено» выполняется прогон 2 (вне этого прогона).

## Решения по реализации

- Язык и стиль файла — русский, markdown, стиль существующих `docs/exec-plans/active/*`; идентификаторы (SCN, PMM, ADR, WBS) — английские. Почему: конвенция репо.
- Черновик коммитится в прогоне 1 (атомарный коммит docs + `.autopilot/`), чтобы работа пережила сессию; Approved-коммит — в прогоне 2. Почему: дерево должно оставаться чистым, прогон 2 даёт чистый диф утверждения.
- Комментарий в Jira — contentFormat markdown, пометка «черновик к утверждению», без смены статуса и описания. Почему: AC PMM-11 — фиксация критериев в тикете только ПОСЛЕ утверждения.
- В чек-листе каждое поле артефакта — «—» до выполнения; заполняется ссылкой (демо/ADR/замер/ретро) при закрытии среза. Почему: AC «каждый критерий при закрытии имеет ссылку на артефакт».
- Источники формулировок: PMM-11 (черновик 6 пунктов), PMM-3 (состав/границы W1), PRODUCT-VISION §4 (гейты V1), решения грилля 2026-08-27. Противоречий с записанными решениями нет: «ADR Accepted» согласуется с правилом HANDOFF «PMM-2 closes only at ADR Accepted».

## Границы и швы

Прогон уровня T0: один документ + один Jira-комментарий, один исполнитель, публичных сигнатур и тестовых швов нет — раздел пустой по правилу «граница, которую не пересекает ни один таск, не граница».
