# Спецификация: PMM-12 — DoD-чеклист среза

## Задача

Исполнитель задачи среза (Jira PMM) не имеет единого операционного чеклиста закрытия: базовый DoD живёт в `AGENTS.md` §Definition of Done, доменные требования среза (unreleased-маркировка, SourceRef, reviewer-BLOCK) разбросаны по RULES.md и DEC-006. При закрытии задачи каждый раз собирает чеклист заново из четырёх файлов — или пропускает пункты. Комментарий сверки PMM-12 от 2026-08-22 предупреждает: при этом легко создать «второе конкурирующее определение» DoD.

## Решение

Один документ `docs/governance/dod-checklist.md` — операционный вид DoD задач среза Jira PMM. Он не заменяет канон, а сводит 7 пунктов в формат «проверь X → канон здесь», с готовым шаблоном аудита для копирования в Jira-комментарий. Ретро-аудит трёх закрытых задач sprint-0 и закрытие самой PMM-12 проходят по этому шаблону.

## Решения по реализации

- **Язык и формат дока**: русский, в стиле семейства `docs/governance/` (заголовок-шапка списком + таблицы + «Правила ведения» нумерованным списком). Идентификаторы — английские.
- **Структура чеклиста**: (1) шапка: задача, создан, формат записи, каденция (прогон при закрытии каждой PMM-задачи), связанные документы, scope; (2) 7 пунктов таблицей: № / «Проверь X» / канон; (3) абзац «Приоритет»: каноничны AGENTS.md, RULES.md, DEC-006 — чеклист операционный вид, при расхождении канон выигрывает; (4) секция «Применение»: AC#2-правило; (5) секция «Аудит»: копи-паст шаблон + правило вердиктов (pass / justified / n-a; fail блокирует закрытие; n-a допустим только с причиной в комментарии); (6) «Правила ведения».
- **Формулировки пунктов** (краткий императив → канон):
  1. `make verify` зелёный до коммита (не после компиляции) → AGENTS.md §DoD, DONE-guard hook;
  2. цифры в клиентских выводах только из verified/staging, каждый вывод с маркировкой `unreleased` до M1-release → DEC-006 (3 условия);
  3. каждый факт LLM-вывода со SourceRef; unsupported claim = reviewer BLOCK → RULES.md MUST, AGENTS.md запрет №6;
  4. схемы/контракты только через contracts + `make codegen` → RULES.md MUST;
  5. затронутая задачей документация обновлена → AGENTS.md §DoD;
  6. новый сигнал/диагноз несёт хотя бы счётчик-метрику → business-signal verify-шаг;
  7. Jira-зависимости (blocks/blocked-by) актуализированы → рабочие ритмы AGENTS.md.
- **AGENTS.md §DoD**: одна строка в конце абзаца: задачи среза PMM дополнительно проходят `docs/governance/dod-checklist.md`. Текст §DoD не переписывается.
- **RULES.md §SHOULD**: одна строка: описание новой PMM-задачи ссылается на чеклист (или refinement добавляет). Файл агентских доков — на английском, строка на английском.
- **scripts/agent/verify**: добавить файл в существующий список required-files (одна строка, существующий bash-цикл).
- **Ретро-аудит**: PMM-30 (DEC-006, PR #9), PMM-9 (assumptions-register, PR #12, merge `4a6b23a`), PMM-10 (risk-register, PR #12) — вердикты по фактическим файлам/PR/коммитам, добытым при исполнении; пункты, неприменимые задаче (например observability), = n-a с причиной.
- **Jira**: комментарии через MCP; статус Done после merge; ссылку на чеклист получает только PMM-12 (своё описание), остальные открытые задачи не трогаются. Зависимости самой PMM-12 (пункт 7 чеклиста на себе): parent `AIOS-PROD-010` и relates `AIOS-DEL-002` проверены и актуализированы (links blocks/blocked-by - по факту трекера, без выдуманных связей).
- **Коммиты**: только затронутые файлы (git add поимённо — dirty-tree note); атомарный conventional commit `docs(pmm): PMM-12 DoD checklist for PMM slice tasks (+ verify guardrail)`.

## Границы и швы

Документный прогон без кода: единственный «шов» — `scripts/agent/verify` (structural layer), поведение проверяется его запуском. Границ между модулями нет.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R04 — bulk-правка описаний ~20 открытых задач | грилль Q5: AC#2 разрешает «refinement добавляет»; шум в трекере не оправдан |
| R08 — машинная проверка содержимого чеклиста (линт пунктов) | guardrail достаточно structural (файл существует); контент проверяет ревью |
| Эскалация чеклиста на PA-задачи | грилль Q3: PA живёт по AGENTS.md + фазовым гейтам |
| Автоматизация статуса Done (transition из пайплайна) | статус ставится агентом вручную после merge, как в PMM-9/10 |
