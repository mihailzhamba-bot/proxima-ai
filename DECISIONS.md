## D5. WB-токены живут на сервере, API вызывается с сервера

- **Дата:** 30.08.2026 (инициатива Mike)
- **Решение:** Токены копируются `scp` в `~/signal-inputs/<cabinet>_<category>_token` на сервере (0600, владелец `proxima-admin`; каталог 0700, `openhands-agent` не видит). Вызовы: `ssh proxima 'curl -sS -H "Authorization: $(cat ~/signal-inputs/...)" ...'` - значение не проходит через контекст агента и не пишется на маке. Ответы сохраняются в `~/signal-inputs/fixtures/wb-api/<endpoint>/<date>.json` и копируются в репо как фикстуры без заголовков авторизации. Это единственное разрешённое исключение из «сервер только чтение» в Сессии 1: перед копированием - dry-run «что / куда / права» и явный OK в чате. Перед копированием - sha256-сравнение с уже лежащими `~/signal-inputs/wb_analytics_token` и `/etc/proxima-ai/secrets/wb_*`.
- **Почему:** секрет не покидает сервер; egress к WB с сервера проверен 13-14.08 (Day 1 probe).
- **Отклонено:** вызовы с мака (значение токена в окружении агента); запуск `tools/wb_api_probe.py` под `sudo -u` с записью в `/srv/proxima-ai/data` (нарушает «только чтение» без явного исключения).

## D5b. Какие токены переносим в Сессии 1

- **Дата:** 30.08.2026
- **Решение:** Только токен Амировой (`WB_API_TOKEN` из `~/.zshrc` на маке). Клиентские токены Proxima (`mike`, `olga`, `nesimova`, `adris-tree`) - после решения «сколько кабинетов» на Воротах 2. Токен Bogatova - Mike достаёт отдельно, когда понадобится боевой ряд.
- **Почему:** глубина истории и лимиты WB одинаковы для всех кабинетов - для разведки хватает одного; чужие данные на сервере с LLM-агентом без причины не нужны.
- **Отклонено:** все пять сразу; Амирова + Bogatova (блокер - токена пилота нет).
- **Поправка 30.08.2026 (факт):** копирование не потребовалось. На сервере уже лежат `/etc/proxima-ai/secrets/wb_{statistics,analytics,finance}_token` и `~/signal-inputs/wb_analytics_token` того же кабинета - fingerprint `sha256(oid|sid)` JWT совпал с локальным `WB_API_TOKEN` (значения не сравнивались и не выводились). Разведка API идёт на серверных токенах. Analytics-токен на сервере read-write - используется только для read-эндпоинтов отчётов, ротация на read-only остаётся в бэклоге (PA-13).

## D6. Граница сентября

- **Дата:** 30.08.2026
- **Решение:** «Сентябрь сделан» = M-03: утренняя сводка с отклонениями («минус 23% против обычного вторника») по одному кабинету в веб-морде, обновляется каждое утро. M-04 (ранжирование по деньгам) и M-05 (план действий) - октябрь.
