## 🔴 Блокеры

1. **Текущий pipeline блокируется на 5 складах.**  
   Правка: оператор данных добавляет stock warehouse mappings в versioned `warehouses.csv`, валидирует и загружает через штатный seed CLI до следующего run. Эффект: pipeline сможет перейти к margin/detect.

2. **Telegram API недоступен с VPS.**  
   Правка: infra owner проверяет outbound TCP/443, маршрут и provider filtering до `api.telegram.org`, затем выполняет `getMe/getChat` и один controlled send. Эффект: восстановление notify.

3. **Analytics token RW ломает Day 2 collector.**  
   Правка: WB cabinet admin выпускает exact-category Analytics READ token и заменяет private token file. Срок: до следующего async report. Эффект: текущая команда сможет возобновлять существующий UUID.

4. **Нет received-vs-written контроля.**  
   Правка: после parse report писать staging transactionally и сравнивать parsed count с фактическим count по `task_id`; mismatch переводить в `BLOCKED`. Owner: backend engineer, до тиражирования. Эффект: исключение «лог успешен, таблица пуста».

5. **Empty Statistics sales трактуется как `NO_SIGNAL`.**  
   Правка: добавить completeness gate для неожиданного пустого ответа по активному кабинету и окну. Owner: backend engineer, до scheduler. Эффект: пустой API не маскируется как отсутствие риска.

6. **Day 1 probe несовместим с текущей архитектурой.**  
   Правка: перевести probe на split least-privilege tokens, разрешить path-only ключи общего `.env`, добавить существующие read-only проверки Prices/Promotion. Эффект: Day 1 становится воспроизводимым одним entrypoint.

7. **Root password сейчас разблокирован.**  
   Доказательство: `passwd -S root` → `root P`, 14.08.2026. Правка после подтверждения доступа: infra owner выполняет `passwd --lock root`. SSH root уже запрещён, но console password остаётся активным.

## 🟡 Риски

- Comparator `<=` расходится с требованием `< N`. Product owner должен зафиксировать семантику до следующего release.
- SKU без истории продаж молча исключается из detector. Нужен отдельный status `NEW_SKU_NO_HISTORY` или fallback policy.
- Rate-limit headers читает Day 1 Python probe, но production TS raw metadata их не сохраняет.
- На VPS нет pytest, поэтому Python retry/raw-order suites не воспроизводятся без отдельного test environment.
- Исторический Telegram `SENT` подтверждён только за 13.08.2026; текущая доставка не работает.
- Raw metadata создаётся на каждый run. Dedup есть на уровне content bytes, но не на уровне acquisition records.
