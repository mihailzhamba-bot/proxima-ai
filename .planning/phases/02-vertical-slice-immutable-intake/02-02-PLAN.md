# Plan 02-02 - Observed XLSX parser, staging and localhost preview

## Revision 2026-08-15 (PA-9, Mike GO): pivot to the WB Analytics API leg

Two official cabinet XLSX exports were observed before parser code was written
(see EVIDENCE.md). Both are period aggregates without a calendar-day column, so
the daily `order_count` grain required by this plan and by the locked
`cabinet + SKU + calendar_day` decision cannot come from a manual XLSX export
that the pilot cabinet offers today. Mike approved the pivot: the preview is
built from the already-collected official WB Analytics DETAIL_HISTORY_REPORT
staging (`stg_wb_nm_report_rows`, lineage `wb_analytics_report_tasks.downloaded_sha256`
plus `raw_wb_analytics_responses.content_sha256`), and the XLSX reconciliation
leg is deferred to a separate plan. All must-have truths stay unchanged:
single-transaction transform with crash-rollback and deterministic retry,
`unreleased`-only facts, tenant-scoped uniqueness, and a localhost read-only
preview traced to the artifact checksum. Implementation artifacts move to
`db/migrations/007_preview_order_counts.sql` (migrations 003-006 already
existed) and `services/collector/src/staging/preview-transform.ts`.

## Objective

After Mike supplies one official WB XLSX with daily product-level order counts, derive an observed header/sheet profile without committing raw bytes or business values; parse it from the immutable artifact into additive staging and preview facts; expose only a localhost, read-only `unreleased` daily `order_count` view with lineage to the artifact checksum.

## Required checkpoint

Do not start this plan before a real official XLSX is available. Record in `EVIDENCE.md` only: local private locator, original filename, sheet names, header names, byte size, SHA-256, retrieval timestamp and the accepted field mapping. Do not commit workbook bytes, cell values, token values or customer payloads.
