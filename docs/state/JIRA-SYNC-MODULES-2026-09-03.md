# Синхронизация Jira: модули M-06+ (03.09.2026)

Статус: **выполнено**. Записано по решению D29; до него в Jira по модулям не было ничего.

Что создано: 10 эпиков (PMM-63…PMM-72) и 50 задач (PMM-73…PMM-122) в проекте PMM. Все в статусе `Backlog` — реализация модулей начинается после гейта M-03 30.09, потому что по PRD §13 гейт бинарный и при непрохождении ничего из M-04+ не стартует.

**Откат одной командой.** Все 60 задач несут метки `modules-run-2026-09-03` и `m06-modules`. JQL отката:

```
project = PMM AND labels = modules-run-2026-09-03
```

## Что заводилось и почему именно так

Решения Mike 03.09: эпик на модуль; заводим всё, но со статусами — принятые матрицей отбора получают детальные задачи, остальные по одной задаче-кандидату; первый модуль пишется так, чтобы отдать в работу без доуточнений.

Порядок эпиков — из PRD §13 «Порядок M-06+ по матрице отбора». Первым идёт не лидер по баллу: CM-9 набрал 89, CM-10 — 84, но CM-10 единственный, кому не нужен ни новый источник, ни новый токен, ни решение по данным.

## Расхождение, найденное при сверке

Черновик `event-diagnosis/SPEC.md` из дропа строит событийный слой на четырёх новых снапшотах — цены через `discounts-prices-api`, остатки, реклама, отзывы. Это четыре новых эндпоинта и два отсутствующих токена. PRD §12 по CM-10 говорит обратное: «новых источников не требует», цена и скидка берутся из `priceWithDisc` и `spp` строки заказа, склад — из `warehouseName`.

Резано по PRD. Снапшоты рекламы и отзывов уехали в CM-4 и CM-11, где токен нужен и так. Именно поэтому первый модуль стартует без единого нового токена.

## Что осталось за пределами Jira

Дроп `.orca/drops/` в репозиторий не копируется и не копировался: внутри ZIP-бандлов лежат чужие данные — около 1160 JSON с реальными вопросами покупателей по чужим артикулам, примеры выгрузок, настройки. Из дропа взяты только идеи и правила, оформленные в описаниях задач.

Статусы `[PROPOSED]` у FR-36…FR-40 в PRD §4.F снимаются отдельной правкой после обновления SPEC — это задача PMM-79 в эпике предпосылок.
