# Дирижёр: серверный оркестратор конвейера единиц работы

Автономный контур на VPS (135.106.186.210), ведущий истории лестницы от выбора до мержа без участия мака. Мозг - conversation профиля **Fedor (Codex, gpt-5.6-terra)** в OpenHands; воркеры - Fedor и GLM пополам; исполнение - `tools/orchestrator/*` и три sudo-обёртки на сервере.

Этот файл - контракт дирижёра. Дирижёр читает его каждый тик и **не имеет права его менять**.

## Один тик (каждые 15 минут)

1. **Состояние.** Прочитать `_bmad-output/implementation-artifacts/sprint-status.yaml`, `STATE.md`, `docs/agent-system/conductor-state.json` (кто в работе, сколько фикс-раундов у каждого). Синхронизировать canonical-клон: `sudo /usr/local/sbin/proxima-git-push --fetch-only`.
2. **Приём готовых.** Для каждого воркера со статусом `finished`: собрать ветку (`collect_branch.sh`), запустить **кросс-модельное** враждебное ревью (историю писал Fedor → ревьюит GLM, и наоборот) по чек-листу ниже.
3. **Решение по ревью.** CRITICAL / HIGH / MAJOR → фикс-раунд тому же воркеру (`send_fix.sh`), счётчик +1. Только MINOR или чисто → `make verify` в отдельном worktree; зелёный → push + PR + automerge (если включён); красный → фикс-раунд.
4. **Запуск нового.** Если активных воркеров < 3 и в очереди есть история, все зависимости которой `done`: собрать dispatch по шаблону и запустить (`launch_worker.sh`), чередуя профили Fedor/GLM.
5. **Учёт.** Обновить `sprint-status.yaml` (`in-progress` / `review` / `done`) и `conductor-state.json`, коммит `chore(conductor): tick <ts>` через обёртку push.

## Чек-лист враждебного ревью (промт ревьюеру)

«No praise, only real risks. READ-ONLY.» Обязательные разделы: (1) **секреты** - значения токенов/паролей в коде, логах, argv, серверных логах PG; (2) **AD-дословность** - расхождение с процитированным AD = дефект; (3) **выдуманные факты** - каждый URL/лимит/цифра обязан быть в `API-FACTS.md` или спайне, иначе CRITICAL; (4) **не переписал ли существующее** - файлы вне scope истории, потеря функциональности (пример: бэкап-скрипт лишился age/S3); (5) **AC-полнота** - каждый пункт Given/When/Then; (6) **тесты** - покрывают ли AC или это галочки; (7) **гейты** - обходится ли новый verify-скрипт подделкой. Вердикт: severity + file + как проверить. Сомневаешься - пиши дефект.

## Kill-критерии

- 3 фикс-раунда по одной истории без закрытия дефектов → `blocked`, алерт, история из очереди снимается;
- CI красный на `main` после automerge → automerge выключается, очередь стоп, алерт;
- Воркер `error`/пропал → один перезапуск продолжением (ветка в workspace цела), второй раз → `blocked`;
- Нет свободных слотов и ни один воркер не двигается 2 часа → алерт.

Алерт = Telegram того же бота, что `proxima-host-monitor` (`OnFailure=proxima-alert@%n.service`).

Состояние, снятое read-only через `conductor_cli.py status`:

- **два слота из трёх заняты завершёнными воркерами**: `1.3` (`status=finished`, `dirty=0`) и `2.2` (`status=finished`, `dirty=0`). Их работа давно в `main` (PR #48 и #46), слоты надо освободить, иначе одновременно пойдёт только одна история;

1. Обновить canonical-репо и чекаут до текущего `main` - без этого шага очередь считает по устаревшим статусам.

Ожидаемая первая волна на три слота: `1.5` (бэкфилл, предусловие - вторая копия артефактов 30.08, PA-66), `1.7` (откат прогона, зависимостей нет), `2.3` (норма, зависит от `1.6` - она в `main` с 03.09). ## Rollback (по одной команде)

```bash
sudo systemctl disable --now proxima-conductor.timer   # остановить очередь
sudo rm /etc/sudoers.d/proxima-conductor               # отобрать права
sudo rm /usr/local/sbin/proxima-git-push /usr/local/sbin/proxima-pr /usr/local/sbin/proxima-pr-merge
# в GitHub: Settings → Deploy keys → удалить ключ conductor; revoke fine-grained PAT
```

Незавершённые ветки воркеров остаются в их workspace и в `origin` - ничего не теряется.
