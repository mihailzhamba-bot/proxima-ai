# Plan 03-02 - Staging-to-facts promotion with quarantine and unified lineage

## Objective

Implement the deterministic promotion service that turns staged WB analytics rows into tenant-scoped `fact_order_counts` inside one attempt transaction, routes every rejected row to typed quarantine, records unified lineage to exact evidence sha256, and proves crash-safety by injection tests on real PostgreSQL.

## Tasks

<tasks>

<task type="auto" tdd="true">
  <name>Task 1: Promotion service with typed quarantine</name>
  <files>services/collector/src/facts/promote-order-counts.ts, services/collector/src/cli/promote-order-counts.ts</files>
  <action>Promotion reads one task's staged rows (input: tenant + task id), validates each (date parse in Europe/Moscow, nm_id positive, order_count non-negative integer, no duplicate grain within attempt), writes rejected rows to `stg_quarantine_rows` with typed reasons, inserts accepted rows into `fact_order_counts` keyed by attempt, writes `fact_lineage_records` (fact batch → task → raw response sha256 → report_type/parser version → request attempt) and `quality_check_results` (row counts accepted/quarantined, grain uniqueness, date-window sanity). One attempt = one transaction incl. the SUCCEEDED marker. CLI runs under `proxima_source_publisher` and refuses to connect with other roles.</action>
  <verify><automated>TS tests on real PostgreSQL (roundtrip runner): happy path from synthetic staged fixture; every validation branch produces its typed quarantine row; a task with zero valid rows produces attempt FAILED with quarantine-only persistence allowed, zero facts</automated></verify>
  <done>DATA-01 promotion machinery + DATA-05 lineage chain proven end-to-end on synthetic fixtures.</done>
</task>

  <verify><automated>pytest/TS suite on disposable PostgreSQL: all six injection points roll back clean; retry idempotent by attempt unique keys</automated></verify>

</task>

## Must haves

- Deterministic only: no LLM, no source fetch, no new WB calls; input is already-staged data.
- The dormant file-artifact lineage family stays supported by the same `fact_lineage_records` shape (family discriminator column), exercised by a synthetic file-artifact fixture so the unified contract is tested on both families.
- `make verify` green; this plan's completion review is the cross-model gate 0/0 entry point for promotion semantics.
