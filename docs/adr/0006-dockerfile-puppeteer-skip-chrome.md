# 0006. Сборка образа webapp без Chrome от puppeteer

## Контекст

План G01 предполагал сборку образа webapp на VPS из git bundle по паттерну PA-13. Первая же сборка на VPS (т07) упала в deps-стадии: postinstall-скрипт puppeteer, приходящий транзитом с mermaid-cli из корня воркспейса, качает Chrome в slim-образ без unzip и не может его распаковать (D01 в манифесте PA-49).

## Решение

В deps-стадии Dockerfile webapp задаём ENV PUPPETEER_SKIP_DOWNLOAD=1. Chrome в образ не ставится: webapp в рантайме его не использует, mermaid рендерится в verify-пайплайне разработки, а не в контейнере.

## Почему

Падение доказано сборкой, а не догадкой: slim без unzip падает на распаковке, при этом браузер образу не нужен. Установка unzip и полноценного Chrome рассмотрена и отвергнута: плюс сотни мегабайт к образу ради зависимости, которая в контейнере не вызывается. Вырезание mermaid-cli из зависимостей на время сборки webapp рассмотрено и отвергнуто: лезет глубже в общий lockfile воркспейса ради того же результата. ENV-флаг лечит падение одной строкой (коммит 0077648).

## Последствия

Неочевидная связь «сборка webapp зависит от mermaid-cli в корне воркспейса» остаётся: апгрейд @mermaid-cli может снова поменять поведение postinstall и удивить. Если webapp однажды захочет реальный headless-browser (скриншоты, PDF-экспорт), puppeteer начнёт падать в рантайме, а не на сборке, и флаг придётся снимать осознанно. Правки deps-стадии Dockerfile обязаны сохранять флаг; автоматической проверки нет.
