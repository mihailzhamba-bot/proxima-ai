# 0003. Фикстуры-first: единый шов данных lib/fixtures

## Контекст

PA-49 строит оболочку кабинета без живых данных: БД-слой и auth-логика вне границ прогона, живые данные обещаны PA-50. Экраны при этом должны показывать реальную форму метрик (число, дельта, спарклайн, сигналы) уже сейчас.

## Решение

Все демо-данные живут в lib/fixtures за типизированными геттерами (getMetrics(), getBrief() и т.п.). UI-компоненты знают только форму данных и не знают про «настоячесть». PA-50 подменяет провайдер целиком, UI не меняется.

## Почему

Прямое подключение Postgres в серверных компонентах отвергнуто: ломает границу прогона (БД-слой не трогать), заставляет локальный `run dev` требовать туннель и секреты, а PA-50 пришлось бы выковыривать запросы из верстки. Mock-контур на уровне HTTP/fetch тоже отвергнут: для SSR-каркаса это лишний слой без ценности. Один шов с типизированными геттерами даёт одну точку подмены в PA-50 и стабильные тесты формы данных.

## Последствия

Сигнатуры геттеров стали контрактом: их смена требует синхронной правки UI и тестов. Структура фикстур может разойтись с реальной схемой БД в PA-50, тогда появится работа по выравниванию неизвестного объёма. До PA-50 все числа в кабинете фиктивны и обязаны носить FX-бейдж. Плата за шов принятая: локальный просмотр работает без БД и секретов одной командой, и это свойство теперь обязательно для всех будущих экранов.
