# Release Gates

Release Gate — обязательный read-only шлюз между планированием и Autopilot. Критик (`release-critic`, скилл `release-cutter`) доказательно находит самый дешёвый безопасный путь до проверяемого релиза и имеет право сказать «задача не нужна» — с доказательствами, а не вкусом модели.

Зачем: задачи попадают в Autopilot слишком толстыми — универсальные платформы вместо одного адаптера, гипотетические сценарии вместо проверяемого результата. Gate режет объём до минимума, при котором релиз остаётся полезным и безопасным.

## Три слоя пайплайна

| Слой | Инструмент | Вопрос |
|---|---|---|
| Grill Me | скилл `grill-me` | Что именно мы делаем и какие решения ещё не приняты? |
| Release Cutter | `/release-gate`, `/release-task`, субагент `release-critic` | Нахуя это нужно? Нужно ли сейчас? Можно ли не делать, переиспользовать, сделать дешевле? |
| Autopilot | скилл `autopilot` | Реализует только согласованный минимальный объём (Scope lock) |

## Когда какую команду запускать

- `/release-gate <задача>` — только аудит: отчёт Release Gate без запуска Autopilot. Вход: задача, epic, roadmap, ключ Jira (`PA-XX`/`PMM-XX` — критик сам тянет задачу через Jira MCP read-only), `@файл`, свободный текст.
- `/release-task <задача>` — оркестрация: gate → обработка handoff-status → (grill при NEEDS_INPUT) → сохранение Scope lock → передача ограниченного brief в Autopilot.

## Вердикты

| Вердикт | Значение |
|---|---|
| KEEP | Исходный вариант уже минимален и безопасен |
| REUSE | Результат даёт существующий код / конфигурация / SDK / библиотека |
| SHRINK | Результат сохраняется, часть scope уходит за рамки релиза |
| DEFER | Задача имеет смысл, но сейчас не блокер релиза |
| DROP | Задача не влияет на подтверждённый результат релиза |
| BLOCKED | Решение небезопасно без факта, зависимости или бизнес-решения |

## Handoff-status

| Статус | Действие |
|---|---|
| READY_AUTO | Autopilot стартует автоматически: gate сохранён, передан только раздел 12 + Scope lock |
| NEEDS_APPROVAL | Нужно одно решение Mike до реализации; показывается разница исходного и сокращённого scope |
| NEEDS_INPUT | Максимум три блокирующих ответа; добываются через grill-me; максимум один цикл Gate→Grill→Gate |
| BLOCKED | Показать блокировку, кто снимает, минимальный следующий шаг, независимые задачи |

DISCOVERY_STATUS-строка (машинно-читаемая, для Orca-парсера): `READY_AUTO`→`READY`; `DROP`/`DEFER`→`NOT_NEEDED`; `NEEDS_APPROVAL`/`NEEDS_INPUT`/`BLOCKED`→напрямую.

## Где хранятся отчёты

- Файл: `docs/release-gates/<YYYY-MM-DD>-<slug>.md`
- Gate ID: `RG-<YYYYMMDD>-<slug>` (пример: `RG-20260827-meta-ads-import`)
- Дочерняя задача ссылается на Gate ID в описании / Jira-задаче
- Один gate на epic покрывает дочерние задачи, пока они не выходят за Scope lock

## Scope lock

Утверждённая граница объёма, которую Autopilot не расширяет самостоятельно: реализуется только In scope, никакого расширения, универсализации и «заодно»; при обязательной дополнительной работе - остановка и возврат задачи в Release Gate.

Полный канон: `.opencode/skills/release-cutter/SKILL.md`, раздел «Scope lock для Autopilot».

## Что освобождено от gate

- typo и опечатки;
- форматирование;
- test-only изменения;
- узкий bugfix без изменения поведения, контрактов, архитектуры, данных, зависимостей, security и scope.

Правило антибюрократии: один полный gate на epic или значимую верхнеуровневую задачу, не на каждый технический подшаг. Если исходный план уже минимален — критик выдаёт `KEEP / READY_AUTO`.

## Неприкосновенные решения

`docs/agent-system/DECISIONS.md`, `docs/adr/*` и утверждённые фазовые контракты M1-roadmap критик не DROP/DEFER молча. Реализацию внутри них можно SHRINK'уть; пересмотр решения — только `NEEDS_APPROVAL` с явной ссылкой.

## Связь с пайплайном Orca

В пайплайне major/critical `release-critic` (`/release-gate`) занимает место briefmaker: research репо + Jira → отчёт Release Gate с вердиктом, handoff-status и строкой `DISCOVERY_STATUS` для оркестратора. Координатор диспетчеризует критика, решения Mike идут через decision gates. Полный playbook: `docs/agent-system/ORCHESTRATION.md`, контракт: секция «Release Gate» в `AGENTS.md`.
