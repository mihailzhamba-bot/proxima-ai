## Периметр

Срез = вся инициатива **init-m2 (PMM-1)** — три спринта. Терминологическая развязка: «W1-срез» в PMM — это init-m2 (спринты 0-2, без дат — velocity неизвестна на момент планирования); продуктовая волна W1 из PRODUCT-VISION §4 (недели 1-3) — её ядро, а цель V1 «1-2 мес» остаётся ориентиром Vision. Срез закрывается по критериям ниже, не по календарю.

- Sprint 0 — governance + спайки + контракты (PMM-6: реестры PMM-9/10, ADR-0001 PMM-2, Build vs Buy PMM-14, PMM-7/8/11/12/15/16; PMM-29 — контракты как фундамент LLM-слоя). Примечание: SCN-008 через PA-41 стартует не дожидаясь PMM-29 — контракты блокируют W2 LLM-слой, не импорт движка;
- Sprint 1 — детекторы W1 + LLM-слой + ретро (PMM-20/21/22/23, PMM-5/25, PMM-32/33, PMM-19);
- Sprint 2 — сквозной сигнал + гейт + velocity (PMM-26/27/24, PMM-28 V1 value-gate, PMM-13).

Критерии применяются к закрытию среза в целом, не только эпика PMM-3 (решение грилля 2026-08-27: «весь init-m2»).

## Exit-критерии

### 1. V1 value-gate проведён (PMM-28)

≥1 сигнал (любой из SCN-008 data quality, SCN-001 продажи, SCN-005 OOS) прошёл полный цикл:

1. сгенерирован на staging-данных пилота с маркировкой `unreleased` и SourceRef на каждый факт (DEC-006, анти-паттерн прошлого цикла);
2. LLM-диагноз: primary + 2-3 альтернативы + unknowns;
3. Independent Reviewer пропустил сигнал (BLOCK отсутствует или снят исправлением);
4. AM подтвердил в Decision Inbox;
5. действие выполнено **AM вручную** в кабинете (система read-only, WB WRITE запрещён — жёсткий запрет репо);
6. Богатова уведомлена о найденной проблеме и принятой мере.

Verified expected-vs-actual сверка (PMM-26) **не блокирует** гейт: expected фиксируется в Decision Memory, окно наблюдения может выходить за дату закрытия среза. Артефакт: демо сквозного сигнала + **ссылки-доказательства шагов 4-6** (запись в Decision Inbox, подтверждение AM, свидетельство действия/уведомления клиента — скриншот, письмо или комментарий AM).

### 3. Reviewer-BLOCK работает (AGT-002, PMM-25)

Eval-прогон зафиксирован на инфраструктуре PMM-33:

- ≥1 adversarial-кейс с заведомо неподтверждённым утверждением (unsupported claim) — reviewer **заблокировал** (BLOCK);
- 0 ложных блокировок (false BLOCK) на **полном** чистом наборе датасета W1 — состав, размер и версия датасета фиксирует PMM-33 в своём репо; false BLOCK = BLOCK на кейсе, где каждое утверждение подтверждено SourceRef.

Знаменатель обязателен: «0 FP» на одном подручном кейсе критерий не закрывает. Так «BLOCK работает» доказан рабочим случаем, а не пустым пропуском. Артефакт: отчёт в `docs/evidence/` (со ссылкой на версию датасета) + CI job ID.
