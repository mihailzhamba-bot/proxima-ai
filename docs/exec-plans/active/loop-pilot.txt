## Intent
Построить LOOP по утверждённому плану: отдельный управляющий VPS, существующий WB-модуль, подтверждение решения Mike, задача сотруднику, отдельная проверка результата. База: main 6912a92c0ddb298e26d9b93c2b611b720254b56e.

## Boundaries & Constraints
Always: существующий сбор/PostgreSQL/SourceRef; медиана [D-14,D-1]; порог пилота -30 с источником решения и датой; реальные данные в рабочем режиме; BetterAuth проверяется на сервере; кабинет и исполнитель проверяются на каждой операции; повтор возвращает прежний результат; отмена блокирует публикацию; Paperclip единственный планировщик Director; готовый PR является конечным состоянием.
Ask First: покупка VPS, merge, production deploy. IP нового VPS и отдельные credentials Director задаются оператором после создания; их отсутствие запрещает объявлять стенд работающим.
Never: установка LOOP на Simone, копирование памяти/OAuth существующего Hermes, запись в WB, автоматический merge, тяжёлые сборки на управляющем VPS.

## I/O & Edge-Case Matrix
| Состояние | Действие | Результат |
| Свежая аномалия | Mike подтверждает действие, сотрудника, срок, ожидаемый результат | Решение и задача фиксируются одной транзакцией |
| Дубликат подтверждения | Повтор команды/ответ потерян | Возвращается та же задача |
| Чужой кабинет/задача, неверная сессия | Чтение или изменение | Отказ без утечки данных |
| Сотрудник выполнил действие | Подтверждение с evidence | Статус выполнения меняется, эффект ещё не доказан |
| Данные stale/insufficient, отсутствует источник | Диагноз/сверка | Честная неопределённость, без неподтверждённых чисел |
| Отмена/перезапуск управляющего запуска | Поздний ответ исполнителя | Старая попытка не публикуется |

## Design Notes
Сохраняем действующий дизайн, SQL-провайдер и денежную арифметику. Старую заморозку auth и неопределённый порог заменяет явный план Mike от 13.09.2026. Изменения из незамерженного PR #134 не считаются принятым AD. Авторизация разворачивается только с отдельно выданными membership, без самоназначения owner при регистрации.

Уточнения разведки для реализации: collector_runs.kind закрыт, поэтому отдельный workflow run ledger без изменения старой CHECK. Решения сохраняют snapshot и не уничтожаются при удалении source_brief_run_id; связь становится orphaned. SQL auth пока отсутствует, schema.auth.ts только модель. tools/verify_migrations.py принимает tenant-only RLS; employee ownership можно строго проверять в серверном сервисе, либо узко расширить policy allowlist с negative tests. Текущий diagnosis adapter поддерживает только mock: рабочий первый диагноз должен быть основан на кодовых фактах, честных гипотезах и проверках; его нельзя назвать результатом LLM. Контракт diagnosis.draft.v1 не совпадает с canonical diagnosis, нужна явная граница.

Paperclip pin: 65ec059bde30d98c92165b24a30a540800dd1f6f; Hermes pin: 939e45c91d751fadd94dcd1b873ac3cb44846213. hermes_gateway: POST /v1/runs {input,instructions,session_id}, Idempotency-Key и X-Hermes-Session-Key; GET /v1/runs/{id}; GET /v1/runs/{id}/events SSE; POST /v1/runs/{id}/stop.
