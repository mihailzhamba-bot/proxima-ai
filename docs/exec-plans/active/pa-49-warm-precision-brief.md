## Контекст (факты репозитория, не домыслы)

- Каркас уже стоит: `services/webapp` (Next.js 16.3 App Router, standalone; Better Auth 1.7 lazy; Tailwind 4 через @theme inline; vitest; lint). Роуты: `/` → redirect `/brief`; `(app)`-группа: `/brief`, `/inbox`, `/dashboard`, `/admin`, `/styleguide`; `/login`; `/api/auth/[...all]`.
- Текущий вид построен на дефолтных холодных slate/indigo токенах — это и есть «слабо».
- Канон стиля: **`DESIGN.md` в корне репо** (мета-стиль Warm Precision, v2 2026-08-25). Утверждён Mike 2026-08-25. DESIGN.md — высшая инстанция стиля; при конфликте с любым референсом выигрывает DESIGN.md.
- Пометка `unreleased` (DEC-006) обязана оставаться на всех экранах; данные — fixtures (обезличенные), никаких реальных cabinet ID/SKU/цен.
- UI не считает метрики — только рендерит. Все числа на fixtures — структурные обезличенные значения.

## Референсы (что заимствовать, источник: ресёрч 2026-08-25)

| Референс | Заимствование |
|---|---|
| Linear | Плотность без хаоса: строки 36px, минимум хрома, спокойная пластика «familiar and fluid» |
| Stripe | Метрическая полоса: 4-6 KPI, каждый = число + дельта vs период + спарклайн, ничего лишнего сверху |
| Grafana | Читаемость при плотности (для будущего дашборда; в каркасе — принцип, не графики) |
| Vercel | Progressive disclosure: сводка сверху, детали — клик глубже |
| Superhuman | Inbox как очередь решений: триаж, keyboard-first (заложить паттерн в скелет `/inbox`) |
| Triple Whale | Trust Layer: цифра всегда с источником (SourceRef-паттерн в скелетах) |

Лучшие дашборды 2026 «выглядят скучно — и это комплимент»: плотность с дисциплиной, три состояния (loading/empty/error) у каждого блока, обе темы с первого дня.

## Требования

- **R01** Токены Warm Precision в `globals.css`: ivory-канва `#f7f4ef`, белые поверхности, тёплые stone-границы `#e7e5e4`, вторичный текст `#57534e`, фиолетовый `#6d28d9` — только главный action/активность на экране; статусы 700-step (green `#15803d` / red `#b91c1c` / yellow `#b45309` / info `#1d4ed8`); радиусы 4px контролы / 8px контейнеры; hairline-разделители, тени только у транзиентных слоёв (dropdown/modal/popover).
- **R02** Тёмная тема: тёплый тёмный stone (не холодный slate); обе темы переключателем, light — основная. [OPEN-1: реализовать сейчас или отложить тёмную — вопрос Mike на интервью]
- **R03** Шрифты: Inter (variable, интерфейс) + IBM Plex Mono (все числа/SKU/цены/даты в таблицах) через `next/font`; micro-labels uppercase + tracking 0.06em; максимум 2 веса на экран.
- **R04** Shell: сайдбар 256px с uppercase-секциями (например «Ежедневное»: Brief, Inbox; «Аналитика»: Дашборд; «Система»: Админ, Стайлгайд), пункты 36px, активный = заливка 8% primary + левый бордер 3px; коллапс не нужен в v0.
- **R05** Метрическая полоса вместо текущего топбара-счётчика: 4-6 карточек «число (mono, 28-32px) + дельта vs 7 дней + спарклайн» на fixtures; GYR-счётчики сигналов — первая карточка; переключатель кабинета — dropdown. [OPEN-2: состав карточек — вопрос Mike]
- **R06** `/brief` как редакционный экран: шапка с датой (mono) и вердикт-строкой («2 критичных / 5 внимания»), critical-сигналы полноширинными строками (GYR-полоса слева, заголовок + предполагаемая причина, ₽-оценка «стоимость молчания» mono справа, chevron), ниже дайджест; пометка unreleased компактнее текущей плашки, но заметной. Содержимое — fixtures.
- **R07** Скелеты `/inbox`, `/dashboard`, `/admin`: не пустые заглушки-карточки, а спроектированные empty-состояния (одно предложение + что оживёт в PA-51/52/54); inbox — намёк на очередь решений (Superhuman-паттерн).
- **R08** Крафт-слой: skeleton-loading (пульс в тонах surface), designed error-состояния (не полноэкранная ошибка), focus-ring 2px фиолетовый с offset на всех интерактивных, `::selection` violet-тинт, count-up 300-500ms на числах при обновлении, `prefers-reduced-motion` уважается везде.
- **R09** `/styleguide` перерисован под канон: палитра warm (оба варианта темы если R02 реализован), типографика Inter/Mono, hairline-vs-shadow демонстрация, GYR-бейджи, все состояния (loading/empty/error), ₽-формат.
- **R10** `make verify` зелёный целиком + `npm --workspace @proxima/webapp run lint` 0 ошибок + `next build` зелёный; существующие тесты (gyr, rub) не ломаются; новые токены покрыты тестами там, где это логично (например маппинг статусов).
