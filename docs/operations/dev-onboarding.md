# Как начать разрабатывать здесь

Для человека, который первый раз открывает репозиторий. Агенты читают вместо этого `AGENTS.md`. Обновлено 03.09.2026.

## 1. Что это за продукт за две минуты

Приватная платформа для владельца кабинетов Wildberries: каждое утро система сама собирает данные кабинета по официальному API, считает норму (медиана 14 полных дней) и показывает на экране `/brief` строку «вчера N заказов против нормы M, отклонение x %». Дальше по лестнице - аномалии в рублях, гипотеза причины, запись решения и сверка исхода.

Что читать в первый день, по порядку: `README.md` → `STATE.md` (состояние и следующий шаг) → `DECISIONS.md` (решения D1-D26) → PRD §1 и §4 (`_bmad-output/planning-artifacts/prds/prd-PROXIMA-AI-2026-08-28/prd.md`) → `_bmad-output/planning-artifacts/epics.md` (истории, из которых берётся работа).

Два правила, которые объясняют почти все ограничения: **в WB только чтение** и **у каждой цифры есть источник** (артефакт ответа или детерминированный расчёт; языковая модель объясняет, но не считает).

## 2. Что установить

| Что | Версия | Зачем |
|---|---|---|
| Node.js | 22 (не 23) | collector и веб-морда |
| Python через uv | 3.14, uv ≥ 0.11 | control-plane и инструменты |
| PostgreSQL | 16, локально | без него шаг `pg-roundtrip` пропускается и миграции не проверяются |
| Git | любой современный | - |

Системный Python 3.9 не подходит: всё запускается через `uv run --python 3.14`.

## 3. Первый запуск

```bash
export PUPPETEER_SKIP_DOWNLOAD=1      # иначе npm ci тянет Chromium
make install                         # также активирует .githooks/pre-commit в этом репозитории
cp infra/local.env.example .env       # значения секретов не заполняются локально
make verify
```

`make verify` - единый гейт проекта: установка, кодогенерация типов из контрактов, проверка отсутствия diff после кодогенерации, проверка типов, lint веб-морды, тесты (collector, веб-морда, Python), контракты, миграции, обкатка миграций на одноразовом PostgreSQL, происхождение импортированного кода, рендер архитектурных карт, границы runtime, скан секретов, контракт VPS, сигнал остатков, клиент WB. Задача считается сделанной только при зелёном гейте.

Полезные подмножества: `npm --workspace @proxima/collector test`, `npm --workspace @proxima/webapp test`, `uv run --python 3.14 --project services/control-plane --extra test pytest services/control-plane/tests tools/tests`.

Веб-морда локально работает на демо-данных: режим `WEBAPP_DATA_MODE=fixtures`, живой базы не требует.

## 4. Ловушки первого дня

- Без локального PostgreSQL 16 шаг `pg-roundtrip` печатает `SKIP` и **выходит с кодом ноль**: гейт зелёный, а миграции не проверены.
- Lint веб-морды входит в `make verify`; отдельно его можно запустить командой `npm --workspace @proxima/webapp run lint`.
- `next build` переписывает отслеживаемый `services/webapp/next-env.d.ts` - после сборки вернуть файл.
- `make install` идемпотентно активирует локальный хук перед коммитом через `core.hooksPath=.githooks`.
- При длинном пути к проекту: `TMPDIR=/tmp make verify`.
- Файл с именем `.env*` в Git роняет гейт: `tools/secret_scan.py` отклоняет такое имя
  до чтения содержимого, поэтому образец окружения лежит как `infra/local.env.example`.
- `docs/agent-system/HANDOFF.md` частично исторический; текущее состояние - `STATE.md` и `DECISIONS.md`.
- Архитектурные карты `docs/architecture/*.mmd` описывают снятую рамку M1, хотя рендерятся внутри гейта.

## 5. Как устроена работа

Единица работы - одна ветка, один PR, один результат, который владелец проекта проверяет одним действием. Ветки: `feat/…`, `fix/…`, `docs/…`, `chore/…` от `origin/main`. Коммиты - по-английски с префиксом (`feat(webapp): …`), документация и общение - по-русски, идентификаторы в коде - по-английски.

Порядок: взять историю из `epics.md` → ветка → код и тесты → `make verify` зелёный → PR → независимое ревью (агент-ревьюер или второй человек) → приёмка владельцем → мерж делает владелец. Короткая версия правил для PR - `CONTRIBUTING.md`; шаблон PR подставляется автоматически (`.github/pull_request_template.md`); владельцы путей, которых GitHub запрашивает на ревью, - `.github/CODEOWNERS`; `main` защищён ruleset `main-protected` (D34). Статусы историй живут в `_bmad-output/implementation-artifacts/sprint-status.yaml`, задачи - в Jira (проекты PA и PMM).

Что нельзя без отдельного разрешения: живые вызовы WB API, любые операции записи на сервере, деплой, удаление данных, принудительный пуш. Значения токенов не выводятся никуда и никогда.

## 6. Где что искать

| Вопрос | Где ответ |
|---|---|
| Что строим и зачем | PRD (`_bmad-output/planning-artifacts/prds/…/prd.md`) |
| Что считается сделанным для сентября | `_bmad-output/specs/spec-wb-morning-brief/SPEC.md` |
| Почему так устроено | `ARCHITECTURE-SPINE.md` (AD-1..AD-18) |
| Какие есть таблицы и кто в них пишет | `docs/state/DATA-DICTIONARY.md` |
| Что известно про WB API | `docs/state/API-FACTS.md`, `docs/adr/0007-…` |
| Что проверяется руками перед релизом | `docs/state/WORKS-TODAY.md` |
| Правила для агентов | `AGENTS.md` |
| Роль второго человека и независимая проверка | `docs/agent-system/roles/analyst-vladislav.md` |

## 7. Первый вклад

Хорошая первая задача - инструмент или тест, не трогающий критический путь сентября: что-то в `tools/`, тест на фикстурах, или история из Epic 6 (верификационный контур). Взять историю целиком, не половину: единица работы заканчивается зелёным гейтом и приёмкой.
