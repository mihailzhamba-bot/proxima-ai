## Инцидент живого хвоста (22.09, 10:17 UTC) и фикс PR #163

Первая попытка живого хвоста упала с `WB_SCHEMA_DRIFT`: оба fetch прошли (1441 orders / 911 sales, HTTP 200), транзакция откатилась - ноль новых наблюдений. Диагноз по CAS-артефактам (без повторных вызовов WB): WB ретроактивно переименовал склады в «закрытых» записях, не подняв `lastChangeDate` - 3 заказа из 1441, у которых всё совпадает до знака, кроме `warehouseName` («Екатеринбург - Перспективная 14» → «Свердловская обл.», «Рязань (Тюшевское)» → «Рязанская обл.», «Волгоград» → «Волгоградская обл.»).

Решение Mike (22.09, в чате): точечный фикс - warehouse-only переименование перестаёт считаться дрейфом. PR #163 (`fix/wb-warehouse-rename-drift`, коммиты `09645f7` + `e93b830`): drift-предикат сравнивает payload без `warehouseName`; при совпадении остального запись скипается как replay (payload в stg не перезаписывается - DO UPDATE потребовал бы UPDATE-грант и сломал бы append-only AD-11/AD-12, первая попытка фикса именно это и показала на красном CI: 11 db-тестов `permission denied`). Числа фактов от `warehouseName` не зависят. Любое другое отличие того же PK - по-прежнему `WB_SCHEMA_DRIFT`, fail-closed сохранён.

Верификация фикса: 130 юнит-тестов, typecheck, SQL-семантика на одноразовом postgres:16 (3 случая), зелёный CI PR #163 (verify с pg-roundtrip, build-images, apply-migrations-in-container, systemd-verify ×2). После мержа сервер переведён на `v2026.09.22-3`, образы пересобраны, попытка 2 - SUCCEEDED.
