# Журналы релизов

Здесь лежат журналы релизов PROXIMA AI - по одному файлу на релиз.

- **Формат имени файла:** `YYYY-MM-DD-<release>.md`, где `YYYY-MM-DD` - дата релиза, `<release>` - идентификатор модуля лестницы (пример: `2026-09-22-m01.md` - релиз M-01, вт 22.09.2026).
- **Кто пишет:** исполнитель релиза - тот, кто ведёт runbook релиза в день деплоя (см. «Исполняет» в шапке соответствующего runbook; для M-01 - `docs/operations/release-m01.md`, исполнитель по D7). Записи делаются по ходу выполнения, а не по памяти после.
- **Шаблон:** `TEMPLATE.md`. Новый журнал - копия шаблона, заполненная заранее тем, что известно до релиза (даты, ссылки, предусловия); всё остальное остаётся `UNKNOWN` или пустым и заполняется фактами в день релиза.
- **Что вписывать:** только факты - время шага, результат команды, отклонения от runbook. Числа, версии, shа - из вывода команд в день релиза; неизвестное - `UNKNOWN` (правило из AGENTS.md: «Unknown → `UNKNOWN`», никогда не выдумывать).
- **Связанные документы:** runbook релиза (`docs/operations/release-m01.md` и следующие), список изменений - `CHANGELOG.md` в корне репозитория (ведётся по Keep a Changelog 1.1, раздел `Unreleased` наполняется по мере попадания изменений в `main`).
