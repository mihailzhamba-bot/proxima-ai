# c6-c8-unit-economics-reports - round 3

Дата доступа ко всем источникам: 2026-09-02. Ограничение раунда: лимит WebSearch сессии был исчерпан до начала раунда (200/200), поэтому раунд шёл только по прямым URL из лидов и через поиск кода GitHub (`gh api search/code`). dev.wildberries.ru по-прежнему отдаёт HTTP 498 (release-notes и openapi/financial-reports-and-accounting), triplewhale.com - HTTP 403 на /agencies и /pricing, sirena-ai.ru/pricing и /tariffs отдают пустую оболочку без контента.

## Что искал и что нашёл

**Версия финотчёта (приоритетный лид).** Отключение v5 подтверждено двумя независимыми SDK-репозиториями, генерируемыми из OpenAPI-спецификации WB. Changelog `eslazarev/wildberries-sdk` в записи «Changed (2026.07.16)» фиксирует: «Финансы (Finances): удалён устаревший эндпоинт `GET /api/v5/supplier/reportDetailByPeriod` (Отчёт о продажах по реализации) вместе со схемой ответа `DetailReportItem` и связанными параметрами/описанием лимитов» (eslazarev/wildberries-sdk CHANGELOG.md, коммит 2026-09-02, https://github.com/eslazarev/wildberries-sdk/blob/0b2855dc129fa9f34bdd07bcd30b1f791345460c/CHANGELOG.md, доступ 2026-09-02); более ранняя запись того же changelog: «метод `/api/v5/supplier/reportDetailByPeriod` помечен как `deprecated` и будет удалён 15 июля» (там же). Гайд миграции `salacoste/daytona-wildberries-typescript-sdk` даёт то, чего не хватало в раунде 2 - таблицу соответствия полей v5 → v1: «Hard deadline: 2026-07-15. The v5 endpoint `GET /api/v5/supplier/reportDetailByPeriod` will be disabled by Wildberries on this date»; домен меняется с `statistics-api.wildberries.ru` на `finance-api.wildberries.ru`, метод GET → POST, суммы `number` → `string`, «Token types: All types → Personal/Service only (NOT Basic/Test)», добавлен параметр `fields: string[]` и методы `getSalesReportsList()` / `getSalesReportsDetailedByReportId()` (salacoste, docs/guides/migration-finance-reports-v5-to-v1.md, коммит 2026-08-09, https://github.com/salacoste/daytona-wildberries-typescript-sdk/blob/176b5487f7351502dd279360366b384405051192/docs/guides/migration-finance-reports-v5-to-v1.md, доступ 2026-09-02). Ключевые переименования для юнит-экономики из той же таблицы: `ppvz_for_pay` → `forPay`, `storage_fee` → `paidStorage`, `acceptance` → `paidAcceptance`, `deduction` → `deduction`, `delivery_rub` → `deliveryService`, `retail_price_withdisc_rub` → `retailPriceWithDisc`, `acquiring_fee` → `acquiringFee`, `penalty` → `penalty`, `additional_payment` → `additionalPayment`, `rebill_logistic_cost` → `rebillLogisticCost`, `realizationreport_id` → `reportId`, `nm_id` → `nmId`, `sa_name` → `vendorCode`, `barcode` → `sku`, `assembly_id` → `orderId` (там же). Гайд также предупреждает о типовой ошибке миграции - конкатенации строковых сумм («"376.99" + "14.89" = "376.9914.89"») и рекомендует `parseMoneyAmount()` (там же). Официальный текст WB прочитать не удалось (HTTP 498), поэтому статус «verified» держится на трёх независимых издателях (АВОШОП, SelSup из раунда 2 + два spec-derived SDK), а не на первоисточнике.

**Историческая точка v5 (второй издатель по полям).** Статья на Infostart для 1С-интеграций фиксирует `GET https://statistics-api.wildberries.ru/api/v5/supplier/reportDetailByPeriod` как актуальный на 08.05.24 и недоступность v1 с 29.01.24, а также перечисляет поля `ppvz_for_pay`, `delivery_rub`, `penalty`, `additional_payment`, `storage_fee`, `deduction`; по пересказу инструмента, статья отмечает, что удержания/реклама в детализации не разнесены по SKU (Infostart, ~2024-05, https://infostart.ru/1c/articles/2068048/, доступ 2026-09-02; текст пришёл с битой кодировкой - уверенность средняя).

**Реклама без двойного счёта / «Прочие удержания».** Явной методики разнесения `deduction` по `nmId` в этом раунде снова не найдено. Новый лид: в changelog `eslazarev/wildberries-sdk` есть запись «Отчёты: переименованы `operationId` - `getMeasurementPenalties`→`getV1MeasurementPenalties`, `getWarehouseMeasurements`→`getV1WarehouseMeasurements`, `getDeductions`→`getV1Deductions`» - то есть в Reports API существует отдельный метод отчёта по удержаниям (`getV1Deductions`), который может нести тип операции и привязку к товару (eslazarev, https://github.com/eslazarev/wildberries-sdk/blob/0b2855dc129fa9f34bdd07bcd30b1f791345460c/CHANGELOG.md, доступ 2026-09-02). Путь и поля метода в этом раунде не прочитаны.

**Storage attribution (API платного хранения).** В сгенерированном из спецификации WB клиенте `serega3000/wildberries-api` (analytics.ts) есть тип `ResponsePaidStorage` с полями `date`, `logWarehouseCoef`, `officeId`, `warehouse`, `warehouseCoef`, `giId`, `chrt_id`, `size`, `barcode`, `subject`, `brand`, `vendorCode`, `nmId`, `volume`, `calcType`, `warehousePrice` («Сумма хранения»), `barcodesCount» («Количество единиц товара (штук), подлежащих тарифицированию за расчётные сутки»), `palletPlaceCode`, `palletCount`, `originalDate`, `loyaltyDiscount`, `tariffFixDate`, `tariffLowerDate» (serega3000/wildberries-api, коммит 2024-09-03, https://github.com/serega3000/wildberries-api/blob/22cb9b6e29ac749747084a1ed9c9c9dbfcebe1ff/src/.generated/api/analytics.ts, доступ 2026-09-02). Это означает, что стоимость хранения приходит по дням и по `nmId` - разнесение хранения на SKU возможно напрямую из API, без пропорций. MCP-сервер `theYahia/WWmcp` (коммит 2026-09-01) реализует `get_paid_storage (async report)` - отчёт асинхронный (создать → опросить статус → скачать), при этом «status strings … marked `VERIFY` in source» (theYahia/WWmcp CHANGELOG, https://github.com/theYahia/WWmcp/blob/f77aef9e0da3e56fc299321f9648ce20b068c726/servers/wildberries/CHANGELOG.md, доступ 2026-09-02). Точный путь эндпоинта в grep-выдаче не попал; кандидат из раунда 2 (`/api/v1/paid_storage`) остаётся неподтверждённым.

**Moneyplace - противоречие цен закрыто.** Живая страница тарифов: Premium «5 000 ₽ + 1 маркетплейс», Deluxe «7 000 ₽ + 1 магазин», Enterprise - по запросу; «+1 маркетплейс» означает подключение одной площадки (Wildberries, Ozon, Яндекс Маркет, Lamoda, Magnit Market) по 5 000 ₽ за каждую дополнительную; «+1 магазин» - один аккаунт продавца, доплата за дополнительный магазин по пересказу инструмента: Premium 7 000 ₽, Deluxe 5 000 ₽, Enterprise 5 000 ₽; блок «Управление магазином» с «Удельная прибыль» есть во всех тарифах (Moneyplace, https://moneyplace.io/tariffs, дата публикации неизвестна, доступ 2026-09-02). Цифра реселлеров «от 13 900 ₽/мес» из раунда 2 не соответствует живой странице - вероятно, устаревший или партнёрский прайс; принимать живую страницу.

**Агентская отчётность - глобальные инструменты.** Sellerboard для агентств: «one single agency profile to manage all your client's accounts and switch between accounts with a single click», «Manage team member access and maintain client confidentiality with customizable account access rights», «Add your agency's logo to the sellerboard dashboard», «Export and automatically send predefined reports based on key KPIs - delivered to your email or synced to your spreadsheets on a regular schedule», партнёрские комиссии; по пересказу инструмента тарифы от «Standard ($15/mo, 4 additional accounts)» до «Enterprise ($63/mo, 16)» (Sellerboard, https://sellerboard.com/agencies, дата неизвестна, доступ 2026-09-02; цифры цен - средняя уверенность, возможно годовая оплата). DataHawk: цены не публикуются («Custom pricing available with annual plans tailored to your business»), агентский план описан как «Multi-account dashboard with white-label reports, AI alerts, and role-based access», заявлена «SKU-level profitability» и «Executive-ready dashboards» (DataHawk, https://datahawk.co/pricing, дата неизвестна, доступ 2026-09-02). Общий паттерн двух глобальных вендоров: агентский продукт = мультиаккаунт + ролевой доступ + брендирование (логотип / white-label) + расписание рассылки KPI-отчётов; ни один из них не публикует шаблон «что сделали → эффект → план». Triple Whale прочитать не удалось (HTTP 403).

**Sirena AI.** /pricing и /tariffs возвращают только заголовок «SIRENA AI — аналитика маркетплейсов Wildberries, Ozon, Amazon» - контент рендерится клиентом; цены не получены.

## Лиды для следующего раунда

- ПРИОРИТЕТ (реклама без двойного счёта): прочитать спецификацию метода `getV1Deductions` (Reports API, «Удержания») - путь, поля (`nmId`?, тип удержания, `bonusTypeName`/аналог), период; сопоставить с `deduction` в sales-reports/detailed и с adv-API (`/adv/v2/fullstats` или аналог) за одну неделю. Источник: спецификация в `eslazarev/wildberries-sdk` (обновляется ежедневно, последний коммит 2026-09-02) - читать сгенерированные модели вместо dev.wildberries.ru (498).
- Storage: подтвердить путь эндпоинта платного хранения (кандидат `GET /api/v1/paid_storage` на `seller-analytics-api.wildberries.ru`) и цикл создать/статус/скачать - по тому же spec-derived SDK или по `salacoste/.../examples/verify_paid_storage_standalone.ts`; проверить, совпадает ли сумма `warehousePrice` за неделю с `paidStorage` (бывш. `storage_fee`) в финотчёте - это и есть тест «сходимости» по хранению.
- Противоречие: Sellerboard - цены «$15/$63» с /agencies против известных публичных $19-$79 на /pricing; прочитать https://sellerboard.com/pricing и уточнить помесячно/годовую оплату.
- Triple Whale (403 на WebFetch) - пробовать help-center kb.triplewhale.com или обзоры; DataHawk - запросить цены через обзоры (G2/Capterra).
- Sirena AI - клиентский рендер; искать цены в обзорах (uniseller.io, crmindex) - WebSearch в этой сессии недоступен.
- Официальный текст WB об отключении v5 всё ещё не прочитан из-за 498 - альтернатива: Telegram-канал WB Partners API / уведомления в ЛК (скриншоты в блогах).
- Новые сущности: `salacoste/daytona-wildberries-typescript-sdk` (гайды по финотчёту, acquiring reports, «подменные артикулы v1»), `pavelsur07/app-service-finance` (PHP-клиент `WbFinanceReportClient` - живой пример инжеста sales-reports/detailed), `dmitriykosik74-rgb/wb-mcp-server`.
- Ценность элементов клиентского отчёта (какие блоки клиенты читают) - по-прежнему без данных; нужен опрос/ретроспектива агентств.

## Не нашёл

- Официальный текст WB (release-notes / OpenAPI на dev.wildberries.ru) об отключении v5 и полях sales-reports - HTTP 498 при обоих запросах; подтверждение получено только через spec-derived SDK.
- Точный путь эндпоинта отчёта платного хранения и строки статусов асинхронного отчёта - в grep-выдаче только тип ответа.
- Методика разнесения «Прочих удержаний» (`deduction`) на SKU и правило сверки с adv-API - найден только лид на метод `getV1Deductions`.
- Цены Sirena AI (клиентский рендер), Triple Whale (403), DataHawk (не публикуются).
- Вендор с заявлением «сходится до копейки» и пользовательские числа точности сверки - поиск невозможен (лимит WebSearch), прямых URL нет.
- Шаблон агентского отчёта «что сделали → эффект → план» и данные о ценных для клиентов элементах - у Sellerboard/DataHawk только функции (брендирование, расписание, мультиаккаунт), без содержания отчёта.
- vc.ru «7 ошибок финотчёта» - не искал повторно (нет поиска).
