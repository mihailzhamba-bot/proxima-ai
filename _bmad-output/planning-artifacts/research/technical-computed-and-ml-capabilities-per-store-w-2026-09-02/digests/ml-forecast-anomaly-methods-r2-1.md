## Что искал и что нашёл

### 1. Противоречие-приоритет: интервалы для Croston/TSB в statsforecast (снято)

В прошлом раунде страница модели TSB утверждала, что TSB «даёт интервалы». Официальный туториал по интермиттентному спросу утверждает обратное: «The models for intermittent series that are currently available in StatsForecast can only generate point-forecasts. If prediction intervals are needed, then a probabilistic model should be used» (Nixtla, дата публикации не указана, https://nixtlaverse.nixtla.io/statsforecast/docs/tutorials/intermittentdata.html, доступ 2026-09-02). Проверка по исходнику ветки `main` снимает противоречие: классы `TSB` и `CrostonClassic` в `python/statsforecast/models.py` принимают параметр `prediction_intervals: Optional[ConformalIntervals] = None` с докстрингом «Information to compute conformal prediction intervals. This is required for generating future prediction intervals», выставляют `self.only_conformal_intervals = True`, а методы `predict`/`forecast`/`predict_in_sample` принимают `level` (Nixtla, GitHub raw `main`, https://raw.githubusercontent.com/Nixtla/statsforecast/main/python/statsforecast/models.py, доступ 2026-09-02). Вывод: у Croston/TSB нет аналитических интервалов, но есть конформные - через `ConformalIntervals`; туториал устарел относительно кода. Для решения «строить интервалы на интермиттентных рядах» это означает: интервалы получаются только через backtest-калибровку (n_windows), т.е. требуют дополнительной истории.

Отдельная страница-туториал по конформным интервалам statsforecast не найдена: четыре варианта URL (`/docs/tutorials/conformalintervals[.html]`, `/docs/tutorials/conformal_intervals`, `/docs/how-to-guides/conformal_intervals`) вернули HTTP 404 (доступ 2026-09-02).

### 2. Интермиттентный бенчмарк statsforecast (единственный найденный, слабый по дизайну)

В туториале Nixtla на подмножестве M5 («most of the data is intermittent») сравнивались ADIDA, CrostonClassic, IMAPA и TSB по MAE на тесте «the last 28 days as test set» (train/test split, не rolling-origin): CrostonClassic MAE 0.944071, ADIDA 0.948729, IMAPA 0.957256, TSB 1.023126, с выводом «on average, the forecasts are one unit off» (Nixtla, дата не указана, https://nixtlaverse.nixtla.io/statsforecast/docs/tutorials/intermittentdata.html, доступ 2026-09-02). Различия между методами - в третьем знаке; это один сплит, а не rolling-origin, и без сравнения с LightGBM/ETS - независимой (не Nixtla) оценки ETS/Croston vs LightGBM на коротких интермиттентных рядах в этом раунде получить не удалось (M5 Uncertainty paper - HTTP 403).

### 3. Интервалы для LightGBM-пути: mlforecast PredictionIntervals

mlforecast строит интервалы конформно: класс `PredictionIntervals` принимает `n_windows` («the number of cross-validation windows used to calibrate the intervals») и `h` («the forecast horizon. The strategy will adjust the intervals for each horizon step, resulting in different widths for each step»); в примере `PredictionIntervals(n_windows=10, h=48)` (Nixtla, дата не указана, https://nixtlaverse.nixtla.io/mlforecast/docs/how-to-guides/prediction_intervals.html, доступ 2026-09-02). Та же страница предупреждает: «In practice, most prediction intervals are too narrow since models do not account for all sources of uncertainty» и что «prediction intervals are not the same as confidence intervals» (там же). В самой странице примеры на sklearn-моделях (Ridge, Lasso, KNN, MLP), LightGBM явно не упомянут; ограничений по минимальной длине ряда для калибровки не приведено. Практическое следствие для 26 недель дневных данных: 10 окон × h=14 дней = 140 дней калибровки, т.е. почти вся история уходит на калибровку интервалов - требование к минимальной истории нужно выводить самим (не найдено в источниках).

### 4. Rolling-origin backtest (fpp3)

Hyndman & Athanasopoulos описывают «evaluation on a rolling forecasting origin»: последовательные тестовые множества, обучающие данные - только предшествующие наблюдения, «no future observations can be used in constructing the forecast», метрики усредняются по всем тестам; в R реализовано через `stretch_tsibble(.init, .step)` (OTexts, fpp3 3-е изд., 2021, https://otexts.com/fpp3/tscv.html, доступ 2026-09-02). Про минимальное окно сказано лишь, что «the earliest observations are not considered as test sets», конкретного порога нет (там же). В примере CV-RMSE 11.27 против in-sample 11.15: «the accuracy measures from the residuals are smaller, as the corresponding 'forecasts' are based on a model fitted to the entire data set» (там же). Это первичный источник для правила «оценивать только rolling-origin, а не in-sample».

### 5. Потерянный спрос при OOS: FreshRetailNet-50K (замена недоступной IJF 2023)

Статья IJF 2023 «Demand forecasting under lost sales stock policies» снова недоступна (ScienceDirect 403), но нашёлся независимый источник по цензурированному спросу. FreshRetailNet-50K: «50,000 store-product time series», «detailed hourly sales data from 898 stores in 18 major cities, encompassing 863 perishable SKUs», с почасовыми аннотациями стокаутов; авторы применяют «two-stage demand modeling» - сначала «reconstruct the latent demand during stockouts using precise hourly annotations», затем прогноз; заявлен результат «a 2.73% improvement in prediction accuracy while reducing the systematic demand underestimation from 7.37% to near-zero bias»; датасет и код открыты на Hugging Face/GitHub (arXiv, подано 2025-05-22, ревизия 2026-06-18, https://arxiv.org/abs/2505.16319, доступ 2026-09-02). Число 7.37% - оценка авторов на их данных (свежие продукты, почасовые данные), переносить на WB нельзя, но это второй независимый от IJF источник для тезиса «прогноз по продажам без учёта OOS систематически занижен». Практика «baseline × дни OOS × цена» в первичных источниках по-прежнему не найдена.

### 6. Changepoint-детекция: ruptures

ruptures - «a Python library for off-line change point detection», методы Pelt, Binseg, Window, Dynp, BottomUp, KernelCPD; функции стоимости L1, L2, Normal, RBF, Cosine, Linear, CLinear, Rank, ML, AR плюс кастомные; число точек задаётся либо явно, либо штрафом (`pen=10` в примере); опорная статья - Truong, Oudre, Vayatis, «Selective review of offline change point detection methods», Signal Processing 167:107299, 2020 (Centre Borelli, дата не указана, https://centre-borelli.github.io/ruptures-docs/, доступ 2026-09-02). По GitHub API последний релиз v1.1.10 - 2025-09-10, предыдущий v1.1.9 - 2023-12-11, последний push 2026-07-06, 2078 звёзд, 35 открытых issue (GitHub API, доступ 2026-09-02). Важно: библиотека offline (сегментация всей истории), а не online-алертинг; CUSUM/EWMA первичных источников в этом раунде не читал (нет поиска).

## Лиды для следующего раунда

- Противоречие (снято, но требует фиксации в выводах): туториал statsforecast «intermittent models = point-only» vs исходник `main` с `ConformalIntervals` у TSB/Croston. Проверить, в каком релизе появился `only_conformal_intervals` (CHANGELOG / git blame), чтобы понять, покрыт ли pinned-релиз v2.1.1.
- Не-Nixtla оценка ETS/Croston vs LightGBM на коротких интермиттентных рядах: M5 Uncertainty paper через arXiv/ResearchGate/сайт MOFC (mofc.unic.ac.cy), а также Kolassa «Evaluating predictive count data distributions in retail sales forecasting» (IJF 2016) и Spiliotis et al. по M5 на уровне SKU-store. Единственный найденный бенчмарк (claim 3) - один сплит без ML-сравнения.
- Минимальная история для конформных интервалов: 10 окон × h - формула из примеров Nixtla съедает 140 дней при h=14; нужен источник по числу окон vs покрытие (Nixtla blog о ConformalIntervals, MAPIE docs, Stankeviciute/Xu&Xie EnbPI для рядов).
- Метрика 7.37% систематического занижения (FreshRetailNet) - второй источник по «spiral-down»; для WB-контекста нужен независимый источник по маскированию OOS-дней (Habr Ozon/Lamoda/Самокат 2024-2026; поиск был недоступен).
- Онлайн-детекция сдвига (CUSUM/EWMA, Page 1954, Roberts 1959; Bayesian online changepoint Adams & MacKay 2007) - ruptures offline и не закрывает алертинг; проверить `river` (online ML) как альтернативу.
- Здоровье sktime: 2409 открытых issue при активном мейнтенансе - посмотреть долю bug-issue и время закрытия, а не только количество.
- Prophet «optional regressor predictor models with uncertainty propagation» (v1.4.0) - прочитать release note целиком: может изменить оценку Prophet как бейзлайна с интервалами.
- Российские вендоры (Datafinder, Planetra, Tess Technology, Epsilon Metrics) - не отработано, поиск был недоступен.

## Не нашёл

- Сессионный лимит WebSearch исчерпан (200/200) до начала раунда - ни один поисковый запрос не выполнен; все лиды, требовавшие поиска (Habr-ретроспективы про false alarms/drift, Kolassa/Spiliotis о коротких рядах, российские вендоры, практики оценки потерянной выручки у продавцов маркетплейсов), остались неотработанными.
- M5 Uncertainty paper (S0169207022000577) - HTTP 403 на ScienceDirect; альтернативного доступа без поиска не найдено.
- IJF 2023 «Demand forecasting under lost sales stock policies» - повторно 403; заменён независимым источником FreshRetailNet-50K (arXiv).
- Туториал по ConformalIntervals в statsforecast - 404 по четырём вариантам URL; API подтверждён только по исходнику.
