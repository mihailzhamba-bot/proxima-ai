# c3-c4-reviews-content-search - round 2

Дата доступа ко всем источникам: 2026-09-02. Ограничение раунда: бюджет WebSearch сессии был исчерпан до начала раунда (200/200), поэтому весь раунд выполнен только через прямое чтение известных/угадываемых URL (WebFetch). 18 вызовов инструментов, 8 источников прочитано, 6 URL недоступны (см. «Не нашёл»).

## Что искал и что нашёл

### Схема официального API отзывов и вопросов (в обход HTTP 498 на dev.wildberries.ru)

Документация библиотеки Dakword/WBSeller перечисляет методы клиента Feedbacks() с путями: `hasNew()` → `/api/v1/new-feedbacks-questions`, `count()` → `/api/v1/feedbacks/count`, `unansweredCount()` → `/api/v1/feedbacks/count-unanswered`, `list()`/`get()` → `/api/v1/feedbacks`, `sendAnswer()` и `updateAnswer()` → `/api/v1/feedbacks/answer`, `rateFeedback()`/`rateProduct()`/`rate()` → `/api/v1/feedbacks/actions`, `archive()` → `/api/v1/feedbacks/archive`, `ratesList()` → `/api/v1/supplier-valuations`, `xlsReport()` → `/api/v1/feedbacks/report`, `orderReturn()` → `/api/v1/feedbacks/order/return` (GitHub Dakword/WBSeller, docs/Feedbacks.md, дата публикации unknown, https://raw.githubusercontent.com/Dakword/WBSeller/master/docs/Feedbacks.md, доступ 2026-09-02). Для SLA «неотвеченный > N часов» это даёт три опорных вызова: счётчик неотвеченных (`/api/v1/feedbacks/count-unanswered`), флаг новых (`/api/v1/new-feedbacks-questions`) и список с последующей фильтрацией по дате; эндпоинт ответа один и тот же для публикации и редактирования (`/api/v1/feedbacks/answer`). Поля ответа (productValuation, userName, createdDate, isAnswered), лимиты take/skip и rate-limit в этом документе не описаны - документ WBSeller содержит только имена методов и пути (там же).

Клиент Questions() устроен параллельно: `unansweredCountByPeriod()` и `answeredCountByPeriod()` → `/api/v1/questions/count`, `unansweredCount()` → `/api/v1/questions/count-unanswered`, `list()`/`get()`/`changeViewed()`/`sendAnswer()`/`reject()` → `/api/v1/questions`, `xlsReport()` → `/api/v1/questions/report` (GitHub Dakword/WBSeller, docs/Questions.md, дата unknown, https://raw.githubusercontent.com/Dakword/WBSeller/master/docs/Questions.md, доступ 2026-09-02). Шаблоны ответов (`/api/v1/templates`, CRUD) - общая подсистема для отзывов и вопросов (оба документа).

README WBSeller перечисляет 16 клиентов (Common, Content, Prices, Marketplace, Statistics, Analytics, Advertising, Recommendations, Questions, Feedbacks, Tariffs, Chat, Returns, Documents, Event Calendar, Supplies), хосты `suppliers-api.wb.ru`, `feedbacks-api.wildberries.ru`, `advert-api-sandbox.wildberries.ru`, и встроенный механизм повторов `retryOnTooManyRequests(10, 1000)` - косвенное свидетельство, что 429 на этих API - штатная ситуация (GitHub Dakword/WBSeller, README.md, дата unknown, https://raw.githubusercontent.com/Dakword/WBSeller/master/README.md, доступ 2026-09-02).

Второй независимый источник по схеме: репозиторий eslazarev/wildberries-sdk - мультиязычный SDK (Python, Node.js, Go, PHP, Rust), генерируемый автоматически из OpenAPI-спецификаций WB с синхронизацией через GitHub Actions; 14 файлов спецификаций, где `09-communications.yaml` - «Feedbacks, questions, and seller chats», а `11-analytics.yaml` - «Search-report, stocks-report, and order-feed endpoints»; 42 звезды, 492 коммита; публикации на PyPI, npm, Packagist, crates.io; документация https://eslazarev.github.io/wildberries-sdk/ (GitHub eslazarev/wildberries-sdk, дата unknown, https://github.com/eslazarev/wildberries-sdk, доступ 2026-09-02). Для команды это практический обход HTTP 498: машиночитаемая спека (`09-communications.yaml`, `11-analytics.yaml`) лежит в открытом репозитории и обновляется автоматически.

### Поисковая аналитика (search-report) и Джем

Страница `https://dev.wildberries.ru/openapi/analytics` снова вернула HTTP 498, `openapi.wildberries.ru` и `openapi.wb.ru` - «proxy refused the connection» из этой среды (доступ 2026-09-02). Тем не менее существование группы `/api/v2/search-report/` теперь подтверждено вторым независимым издателем: eslazarev/wildberries-sdk описывает модуль поисковой аналитики `/api/v2/search-report/` «with product order tracking and search text analysis capabilities» (GitHub eslazarev/wildberries-sdk, https://github.com/eslazarev/wildberries-sdk, доступ 2026-09-02). В WBSeller клиента для search-report нет: README не упоминает его, а docs/Analytics.md покрывает воронку продаж, акцизные товары, платную приёмку, удержания, региональные продажи, возвраты, оборачиваемость, платное хранение, долю бренда, остатки, заблокированные товары - но не поисковые запросы (GitHub Dakword/WBSeller, docs/Analytics.md, https://raw.githubusercontent.com/Dakword/WBSeller/master/docs/Analytics.md, доступ 2026-09-02; уверенность средняя - извлечение могло быть усечено). Полный список пяти методов, поля частотность/позиция/видимость и второй источник по цене Джем (22 990 / 42 990 ₽) в этом раунде получить не удалось (см. «Не нашёл»).

### Контроль карточки: «Календарь событий»

Лид о том, что отчёт «Календарь событий» фиксирует изменения фото/описания, не подтвердился на уровне API: клиент Event Calendar в WBSeller - это исключительно «Календарь акций» с путями `/api/v1/calendar/promotions`, `/api/v1/calendar/promotions/datails` (sic, опечатка в пути сохранена), `/api/v1/calendar/promotions/nomenclatures`, `/api/v1/calendar/promotions/upload`; изменения контента карточки в нём отсутствуют (GitHub Dakword/WBSeller, docs/Calendar.md, https://raw.githubusercontent.com/Dakword/WBSeller/master/docs/Calendar.md, доступ 2026-09-02). Официального API-события «карточка изменена» ни в одном из прочитанных SDK не найдено; провайдеры алертов на изменение контента в этом раунде не проверены (MPSTATS отдал только страницу входа).

### Нативный ИИ-ответчик WB: дата и первоисточник

Статья click.ru датирована «19 февраля» (год в извлечённом тексте отсутствует - конфликт 2025/2026 не снят), ссылается на Telegram-канал @rwb_press_service как на источник, не указывает, бесплатен ли инструмент и входит ли он в подписку; цитаты: «достаточно один раз задать параметры, после чего система будет работать самостоятельно» и «Продавец может определить, на какие оценки нейросеть должна реагировать автоматически, например отвечать только на положительные отзывы (4–5 звезд), а негативные комментарии оставлять для ручной обработки» (blog.click.ru, 02-19 год unknown, https://blog.click.ru/market-news/na-wildberries-zapushhen-ii-pomoshhnik-dlya-raboty-s-otzyvami-pokupatelej/, доступ 2026-09-02). Веб-превью канала «Пресс-служба RWB | Wildberries | Russ» (25,2 тыс. подписчиков) показывает только последние посты и не содержит февральской публикации об ИИ-ответах, Джеме или поисковой аналитике (Telegram, https://t.me/s/rwb_press_service, доступ 2026-09-02). Зато найден свежий сигнал по кластеру C3: пост от 20.08.2026 - «Wildberries выпустила крупное обновление функции ИИ-сравнения товаров», в которое добавлен блок «Важное из отзывов» - «краткий пересказ реального опыта других покупателей», генерируемый обновлённой языковой моделью BerryLM (Telegram «Пресс-служба RWB | Wildberries | Russ», 2026-08-20, https://t.me/s/rwb_press_service, доступ 2026-09-02). Практическое следствие: WB сама суммаризирует отзывы для покупателя собственной моделью, то есть содержание негативных отзывов транслируется в витрину автоматически - это усиливает ценность быстрого реагирования продавца, но эмпирической связи с конверсией по-прежнему нет.
