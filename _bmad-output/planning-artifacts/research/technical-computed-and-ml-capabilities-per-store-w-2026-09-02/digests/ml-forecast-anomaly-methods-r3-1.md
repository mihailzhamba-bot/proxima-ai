## Что искал и что нашёл

### 1. Противоречие «intermittent models = point-only» vs конформные интервалы у Croston/TSB - частично снято по истории релизов

Файл `CHANGELOG.md` в репозитории statsforecast отсутствует (HTTP 404 на `https://github.com/Nixtla/statsforecast/blob/main/CHANGELOG.md`), а поиск по issues/PR строки `only_conformal_intervals` через GitHub Search API дал `total_count: 0` - ни один PR/issue не упоминает это имя в заголовке или теле (GitHub API, доступ 2026-09-02, https://api.github.com/search/issues?q=repo:Nixtla/statsforecast+only_conformal_intervals). История релизов (50 релизов через GitHub API) показывает, что конформные интервалы вошли в библиотеку релизом v1.6.0 от 2023-11-13 с записями «Conformal Prediction», «Add conformal intervals Theta family», «Add conformal intervals for CES», «Add conformal intervals to arima family», «Add conformal intervals to StatsForecast class», «Add conformal prediction for AutoARIMA», а релиз v2.1.0 от 2026-07-14 добавил «Add conformal_error prediction intervals method», «Unified error distributions across the StatsForecast suite» и новую модель «ConformalSeasonalPool model (CSP)» (GitHub API, релизы 2023-11-13 и 2026-07-14, https://api.github.com/repos/Nixtla/statsforecast/releases?per_page=40, доступ 2026-09-02). Ещё раньше, в v1.3.2 от 2022-11-28, появились «ETS for intermittent series» и «Theta for intermittent series» (там же). В release notes Croston/TSB/ADIDA/IMAPA поимённо не названы, поэтому точный релиз, в котором интермиттентные модели получили `ConformalIntervals`, по release notes не определяется; вывод для решения - pinned v2.1.1 (2026-07-16) старше v1.6.0 на ~2.5 года и содержит «Unified error distributions across the StatsForecast suite», так что поведение исходника main (Croston/TSB принимают `prediction_intervals: ConformalIntervals`, только конформные) с высокой вероятностью присутствует в v2.1.1; окончательно закрыть - `pip show`/чтение `models.py` в установленной версии.

### 2. Не-Nixtla свидетельства по M5 Uncertainty: GBM с обычными objective не справляются с overdispersion и нулями

Официальный отчёт M5 Uncertainty (ScienceDirect) по-прежнему недоступен, но arXiv API дал независимую работу Ziel: «M5 Competition Uncertainty: Overdispersion, distributional forecasting, GAMLSS and beyond» (arXiv:2107.06675, v1 2021-07-14, v2 2021-11-10; журнальная версия DOI 10.1016/j.ijforecast.2021.09.008, т.е. IJF). Автор утверждает, что «the M5 competition data faces strong overdispersion and sporadic demand, especially zero demand» и что «the majority of popular prediction methods used in the M5 competition (e.g. lightgbm and xgboost GBMs) fails to address the data characteristics due to the considered objective functions»; как альтернатива предложен GAMLSS - «flexible probabilistic forecasting using low dimensional distributions» с моделированием параметров, например, negative binomial (arXiv, 2021-11-10, https://arxiv.org/abs/2107.06675, доступ 2026-09-02). Для решения это означает: если нужны интервалы/квантили на дневных SKU-рядах с нулями, LightGBM с MSE/квантильной регрессией - не автоматический победитель; нужен либо счётный distribution head (negative binomial / Tweedie), либо конформная надстройка.

Вторая независимая работа - Wang, Kang, Petropoulos «Combining Probabilistic Forecasts of Intermittent Demand» (arXiv:2304.03092, v1 2023-04-06, v4 2024-04-15, stat.AP): цель - «construct probabilistic forecasting combinations for intermittent demand while considering both forecasting accuracy and inventory control utility»; вывод - «combinations perform better than individual approaches for forecasting intermittent demand, but there is a trade-off between forecasting and inventory performance» (arXiv, 2024-04-15, https://arxiv.org/abs/2304.03092, доступ 2026-09-02). Состав базовых методов и датасеты в abstract не раскрыты - полный текст не читал. Третья работа из той же выдачи, Theodorou, Wang, Kang, Spiliotis, Makridakis, Assimakopoulos «Exploring the representativeness of the M5 competition data» (arXiv:2103.02941, 2021-03-04), по аннотации поддерживает переносимость выводов M5 на другие ретейл-датасеты по признакам временных рядов (arXiv, 2021-03-04, https://arxiv.org/abs/2103.02941, доступ 2026-09-02) - аргумент, что результаты M5 применимы к рядам маркетплейса, но с низкой уверенностью, так как прочитан только abstract.

Отдельный запрос в arXiv API на прямые сравнения Croston/TSB против LightGBM/gradient boosting на интермиттентном спросе вернул `opensearch:totalResults = 0` (arXiv API, доступ 2026-09-02) - публикаций с такой явной постановкой на arXiv нет; сравнения живут в IJF/Kaggle-репортах, к которым доступа в этом раунде не было.

### 3. Онлайн-детекция сдвига: river закрывает пробел ruptures (offline)

Библиотека river (online ML) предоставляет `river.drift.PageHinkley` - детектор concept drift, реализующий «CUSUM control chart» по наблюдаемым значениям и их бегущему среднему, с односторонним/двусторонним режимом; параметры по умолчанию `min_instances=30`, `delta=0.005`, `threshold=50.0`, `alpha=0.9999`, `mode="both"`; ссылка на первоисточник - E. S. Page «Continuous Inspection Schemes», Biometrika, 1954; в примере на синтетическом потоке сдвиг с {0,1} на {4,8} сигнализируется на индексе 1006 (river docs, дата публикации неизвестна, https://riverml.xyz/latest/api/drift/PageHinkley/, доступ 2026-09-02). В том же модуле river перечислены ADWIN, KSWIN, DDM, DriftRetrainingClassifier, NoRift/DummyDriftDetector (там же). Для алертинга по дневным рядам это даёт потоковый CUSUM «из коробки» без пересчёта всего ряда, в отличие от ruptures; `min_instances=30` означает минимум ~30 дней до первого сигнала на свежих SKU. Версию и активность репозитория river в этом раунде не проверял (лид).

### 5. Prophet v1.4.0 - релиз августа 2024, а не 2026

Release note v1.4.0 датирован 2024-08-01: «Drop support for Python <3.10», «full static typing support», «Add optional regressor predictor models and propagate their uncertainty»; авторы @jorenham и @tcuongd; на странице указано «2 commits to main since the release» (GitHub, 2024-08-01, https://github.com/facebook/prophet/releases/tag/v1.4.0, доступ 2026-09-02). То есть «propagate their uncertainty» касается неопределённости внешних регрессоров, а не изменения базового механизма интервалов Prophet; лид прошлого раунда не меняет оценку Prophet как бейзлайна. «2 commits to main since the release» на 2026-09-02 при релизе от 2024-08-01 - признак низкой активности репозитория (свежесть версии не подтверждена вторым источником; наличие более поздних тегов не проверял).

### 6. FreshRetailNet-50K: второй носитель (карточка датасета), горизонт данных - четыре месяца

Карточка датасета на Hugging Face: 4.85M строк (4.5M train / 350K eval), почасовые `hours_sale` и `hours_stock_status` (бинарные индикаторы по 24 часам), поле `stock_hour6_22_cnt`, признаки погоды (температура, влажность, осадки), флаги праздников/промо/скидок, лицензия CC-BY-4.0, тег «censored-demand», ссылка на arXiv 2505.16319; данные покрывают март-июнь 2024 (Hugging Face / Dingdong-Inc, дата обновления карточки не указана, https://huggingface.co/datasets/Dingdong-Inc/FreshRetailNet-50K, доступ 2026-09-02). Число 7.37% систематического занижения в карточке не повторено - оно остаётся с одним источником (arXiv-статья тех же авторов), и карточка тот же издатель, так что независимого подтверждения spiral-down нет. Существенно для вопроса о короткой истории: схема «восстановление латентного спроса → прогноз» демонстрировалась на ~4 месяцах данных, то есть короче 26 недель.
