# wb-api-read-surfaces - round 3

Дата доступа ко всем источникам: 2026-09-02. Инструмент WebSearch в этом раунде недоступен (лимит сессии 200/200 исчерпан до старта раунда); dev.wildberries.ru отвечает HTTP 498, openapi.wildberries.ru - «proxy refused», поисковые страницы Bing/DuckDuckGo через WebFetch дают капчу или нерелевантную выдачу. Поэтому основной канал - сырые YAML-спецификации зеркала eslazarev/wildberries-sdk (скачаны curl, грепались локально) плюс GitHub code search (`gh search code`) для вторых публикаторов.

## Что искал и что нашёл

**Провенанс зеркала (лид 8).** Workflow `.github/workflows/update-specs.yml` запускается по cron `0 3 * * *` и вызывает `scripts/download-specs-from-config.sh`; скрипт скачивает спецификации «ONLY from the public S3 mirror populated out-of-band» по секрету `S3_URL`, а в комментарии прямо сказано: «Direct download from Wildberries is not attempted here — its WBAAS anti-bot blocks CI. generation.yaml stays the source of truth» (eslazarev/wildberries-sdk, файл без даты, https://raw.githubusercontent.com/eslazarev/wildberries-sdk/main/scripts/download-specs-from-config.sh, доступ 2026-09-02). CHANGELOG репозитория генерируется автоматически: workflow отправляет `git diff specs/` в `https://api.openai.com/v1/chat/completions` с моделью по умолчанию `gpt-4o-mini` и просит «generate a concise changelog entry in Russian» (eslazarev/wildberries-sdk, https://raw.githubusercontent.com/eslazarev/wildberries-sdk/main/.github/workflows/update-specs.yml, доступ 2026-09-02) - т.е. CHANGELOG зеркала это LLM-пересказ диффа, а не текст WB; цитировать можно только сами YAML. Последние коммиты в `specs/` датированы `2026-09-02T03:08:10Z` и `2026-09-01T03:07:26Z` (GitHub API commits?path=specs, доступ 2026-09-02), значит YAML свежие (<=1 день), но поле `info.version` в них - строковые метки `general`, `promotion`, `reports`, `communication` без даты. README не содержит ни URL источника, ни дисклеймера о неофициальности (github.com/eslazarev/wildberries-sdk, доступ 2026-09-02). Вывод: зеркало - вторичная копия официальных YAML неизвестного происхождения (S3 наполняется вручную мейнтейнером), уровень доверия «medium», не «official».

**Read-only флаг и типы токенов (лид 1, 2 - приоритет).** Официальный текст api-information по-прежнему недоступен (HTTP 498 на https://dev.wildberries.ru/ru/docs/openapi/api-information, доступ 2026-09-02). Однако спецификации несут машиночитаемую разметку: у каждой операции есть расширение `x-readonly-method: true|false`, `x-category: <категория>` и, у части методов, `x-token-types: [service|personal]`; например `postV1Invite` помечен `x-readonly-method: false`, `x-category: usermanagement`, `x-token-types: [personal]`, а `getV1Rating` - `x-readonly-method: true`, `x-category: questionsandfeedback`, `x-token-types: [service]` (eslazarev/wildberries-sdk, specs/01-general.yaml, https://raw.githubusercontent.com/eslazarev/wildberries-sdk/main/specs/01-general.yaml, доступ 2026-09-02). Это косвенно подтверждает, что read-only - свойство токена, применяемое к методу целиком (флаг один, категория - отдельная ось), и даёт готовый allowlist: все операции с `x-readonly-method: true`. Строки «Только на чтение» в YAML нет - текст живёт на странице api-information. Второй независимый публикатор нашёлся через GitHub code search: зеркало справки SelSup в репозитории salacoste/wb-erp-system-daytona-FE содержит инструкцию «Укажите название токена, обязательно выберите Только на чтение, укажите нужные доступы, нажмите Создать токен» со ссылкой на `https://seller.wildberries.ru/supplier-settings/access-to-api`, и разбор ошибки: «в кабинете Wildberries создан токен с галочкой “Только чтение”. У него нельзя изменить данные: цену, остаток на складе и т.д.» (SelSup help, зеркало salacoste/wb-erp-system-daytona-FE, дата unknown, https://github.com/salacoste/wb-erp-system-daytona-FE, доступ 2026-09-02). Противоречие с DEEONE «флаг не упоминается» закрывается в пользу avoshop/SelSup: флаг существует и один на токен. Типы токенов «Персональный / Сервисный / Базовый с секретом / Базовый» присутствуют во всех спецификациях как строки таблицы лимитов «| Тип | Период | Лимит | Интервал | Всплеск |»; у «Базового» лимиты на порядки жёстче (например, новости портала: Персональный/Сервисный/Базовый с секретом - 1 запрос/мин, всплеск 10; Базовый - 1 запрос/ч; информация о продавце: Базовый - 1 запрос/24 ч) (specs/01-general.yaml, доступ 2026-09-02). Что именно означает каждый тип и какой выдаётся обычному селлеру - в YAML не описано (это тоже страница api-information); не найдено.

**Заголовки X-Ratelimit-* (лид 6).** Грep по `x-ratelimit` (без учёта регистра) во всех четырёх скачанных спецификациях (01-general, 08-promotion, 11-analytics, 12-reports) даёт ноль совпадений (доступ 2026-09-02). Косвенно заголовки подтверждают клиентские реализации: MCP-сервер theYahia/WWmcp документирует «409 penalties (via `X-Ratelimit-Retry-After` / `X-Ratelimit-Remaining`)» и «per-category rate limiting» (theYahia/WWmcp, servers/wildberries/README.md и CHANGELOG.md, дата unknown, https://github.com/theYahia/WWmcp, доступ 2026-09-02), а avpavlo8/ficusin-store в коде пишет «a 429 uses WB's exact X-RateLimit-Retry value instead of an arbitrary retry» (https://github.com/avpavlo8/ficusin-store, дата unknown, доступ 2026-09-02). Имена заголовков между двумя проектами расходятся (`X-Ratelimit-Retry-After` vs `X-RateLimit-Retry`) - оба вторичные, официальную формулировку подтвердить не удалось.

**Реклама: fullstats и READ-эндпоинты (лид 5).** В specs/08-promotion.yaml `/adv/v3/fullstats` определён как **GET** (не POST), `operationId: getV3Fullstats`, `x-readonly-method: true`, `x-category: advert`, сервер `https://advert-api.wildberries.ru`; описание: «Максимальный период в запросе — 31 день», «Для кампаний в статусах `7`, `9` и `11`», «В песочнице статистика кампаний доступна за последние 30 дней»; лимит: Персональный/Сервисный/Базовый с секретом - «1 мин | 3 запроса | 20 сек | 1 запрос», Базовый - «1 ч | 1 запрос»; параметр `ids` - «ID кампаний, максимум 50 значений», `beginDate`/`endDate` обязательны (eslazarev/wildberries-sdk, specs/08-promotion.yaml, https://raw.githubusercontent.com/eslazarev/wildberries-sdk/main/specs/08-promotion.yaml, доступ 2026-09-02). Уточнение к раунду 1: не «1 запрос/мин», а 3/мин с интервалом 20 с. Прочие READ: `GET /adv/v1/upd` - «Метод формирует список фактических затрат на рекламные кампании за заданный период», лимит 1 запрос/сек, максимум 31 день, поля `updNum, updTime, updSum, advertId, campName, advertType, paymentType, advertStatus`; `GET /adv/v1/payments` (поля `id, date, sum, type, statusId, cardStatus, currency`) - те же лимиты; `GET /adv/v1/promotion/count` - 5 запросов/сек; `GET /api/advert/v2/adverts` - 5 запросов/сек; `POST /adv/v0/normquery/stats` - 10 запросов/мин, поля `atbs, avg_pos, clicks, cpc, cpm, ctr, norm_query, orders, views, currency`; `GET /adv/v1/budget` - 4 запроса/сек; в описании раздела: данные синхронизируются каждые 3 минуты, статусы - раз в 60 секунд, ставки - раз в 30 секунд (specs/08-promotion.yaml, доступ 2026-09-02). Список мутирующих методов из раунда 2 не перепроверялся (нет противоречия). Форум topics/1441 (дефект «нули») по-прежнему недоступен.

**Аналитика: воронка v2/v3, favorites, «Джем» (лиды 3, 6).** В specs/11-analytics.yaml (коммит 2026-09-02) присутствуют только `/api/analytics/v3/sales-funnel/products`, `/api/analytics/v3/sales-funnel/products/history`, `/api/analytics/v3/sales-funnel/grouped/history`; эндпоинты `/api/v2/nm-report/detail` и `/api/v2/nm-report/detail/history` в перечне путей отсутствуют - из v2 остались только CSV-задания `/api/v2/nm-report/downloads`, `/downloads/retry`, `/downloads/file/{downloadId}` (https://raw.githubusercontent.com/eslazarev/wildberries-sdk/main/specs/11-analytics.yaml, доступ 2026-09-02). Это означает, что v2-воронка уже удалена из документации; дату отключения по-прежнему не нашёл. Глубина v3: `/sales-funnel/products` - «Можно получить отчёт максимум за последние 365 дней»; `/products/history` и `/grouped/history` - «Метод возвращает статистику карточек товаров по дням или неделям. Можно получить данные максимум за последнюю неделю. Данные отчёта обновляются 1 раз в час» (specs/11-analytics.yaml, доступ 2026-09-02). Поле `favorites` в спецификации отсутствует; есть `addToWishlist`, `addToWishlistDynamic` («Динамика добавлений товара в избранное»), `addToWishlistCount` и пояснение «`addToWishlist` — Добавили в **Отложенные**» (specs/11-analytics.yaml, доступ 2026-09-02). Про «Джем»: у `POST /api/v2/search-report/product/search-texts` параметр «`limit` — количество запросов, максимум 30. Для тарифов [Джема] **Продвинутый** и **Премиальный** максимум — 100», аналогичная оговорка про 100 запросов стоит в схеме ответа; для CSV-заданий: «Отчёты по остаткам — типы `STOCK_HISTORY_REPORT_CSV` и `STOCK_HISTORY_DAILY_CSV` — можно создать без подписки» (specs/11-analytics.yaml, доступ 2026-09-02). Итог по противоречию из раунда 1: по спецификации «Джем» не закрывает доступ к методам поисковых запросов, а расширяет лимит выборки (30 -> 100 запросов); ограничение «только с Джем» относится к CSV-истории воронки (DETAIL_HISTORY_REPORT/GROUPED_HISTORY_REPORT). Официальная новость news/297 не прочитана, так что не исключено, что в 2025 требование было жёстче и смягчилось.

## Лиды для следующего раунда

- Официальный текст api-information (типы токенов, флаг «Только на чтение», X-Ratelimit-*) - нужен канал в обход WBAAS: сохранённая копия у пользователя, `curl` с сервера proxima (у него другой IP/UA), либо PDF/скриншот. Пока read-only подтверждён тремя вторичными публикаторами (avoshop 2023-12-11, SelSup help, x-readonly-method в YAML).
- Противоречие имён заголовков: `X-Ratelimit-Retry-After` (theYahia/WWmcp) vs `X-RateLimit-Retry` (avpavlo8/ficusin-store) vs `X-Ratelimit-Retry` (раунд 2). Эмпирическая проверка на 429 с сервера закроет вопрос за один запрос.
- Дата отключения v2 nm-report: спецификация 2026-09-02 её уже не содержит; искать в `git log -p specs/11-analytics.yaml` зеркала (когда пути /api/v2/nm-report/detail исчезли) и в news/302.
- «Джем»: спецификация говорит о лимите 30 -> 100, раунд 1 (news/297) - «только с Джем». Прочитать news/297 и `git log` по строке «Джема» в 11-analytics.yaml: смягчение или неверный пересказ.
- Новая сущность: `x-token-types: [service|personal]` - методы, доступные только одному типу токена (getV1Rating, getV1Subscriptions, getV1TariffConstructorOptions - service; usermanagement - personal). Составить полный список методов с ограничением по типу и понять, какой тип нужен сборщику.
- Мутирующие методы категории «Вопросы и отзывы» (feedbacks/answer, order/return, archive, pins, question PATCH, feedback PATCH, seller/message, claim) - извлечь `x-readonly-method` из 09-communications.yaml и внести в блок-лист.
- Полный allowlist из `x-readonly-method: true` по всем 14 YAML можно сгенерировать скриптом за один проход - кандидат в `tools/verify_business_signal.py`.
- Форум topics/1441 (нули в fullstats v3) - недоступен; проверить эмпирически на фикстуре.
