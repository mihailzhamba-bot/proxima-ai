# c6-c8-unit-economics-reports - round 1

Дата доступа ко всем источникам: 2026-09-02. Бюджет: 18 tool-вызовов израсходован; прочитано 5 первичных страниц целиком (kassy.center, selsup.ru, sellerboard.com/agencies, mayak.bz, mpstats.io/media) и ~10 источников через поисковые сниппеты. Официальная документация dev.wildberries.ru (financial-reports-and-accounting, wb-tariffs) отдала HTTP 498 - по ней только сниппеты и сторонние пересказы, уверенность понижена.

## Что искал и что нашёл

### Официальная поверхность данных: reportDetailByPeriod и tariffs

Детальный финотчёт WB отдаётся методом `GET https://statistics-api.wildberries.ru/api/v5/supplier/reportDetailByPeriod`; поля, на которых строится юнит-экономика по SKU: `ppvz_sales_commission` (комиссия), `delivery_rub` (логистика), `rebill_logistic_cost` (доп. логистика), `storage_fee` (хранение), `penalty` (штрафы), `deduction` (удержания), `additional_payment`, `acquiring_fee` (эквайринг), `ppvz_for_pay` (к перечислению) (Kassy.Center, 2026-03-08, https://kassy.center/blog/reportdetailbyperiod-wildberries/, доступ 2026-09-02). Методология Kassy.Center: «(1) продажи по SKU и выручка; (2) добавить себестоимость единицы; (3) агрегировать из reportDetailByPeriod комиссию, логистику/хранение, штрафы, эквайринг; (4) добавить рекламу; (5) посчитать прибыль периода, на единицу, маржу» (там же). Названные ловушки: дата `rr_dt` (расчётная) не совпадает с датой продажи - периоды расходятся; «финотчёт в одном месте, реклама в другом, продажи в третьем»; анализ на уровне транзакций без группировки по SKU/складу (там же). Кол-венных гарантий точности статья не даёт (там же).

История метода: на форуме Инфостарт зафиксировано, что старая версия `/reportDetailByPeriod` отключена для данных с 29.01.2024, предлагалось перейти на V3, а с 08.05.2024 метод доступен как v5 (Инфостарт-форум, 2024, https://forum.infostart.ru/forum15/topic292220/, сниппет, доступ 2026-09-02). ВАЖНО: сводка первого поиска утверждала, что «метод GET /api/v5/supplier/reportDetailByPeriod объявлен к отключению 15.07.2026», но при чтении страницы Kassy.Center такого утверждения не найдено, а официальная документация недоступна (498) - утверждение НЕ ВЕРИФИЦИРОВАНО, вынесено в лиды как приоритетное противоречие.

Тарифы: официальный WB API содержит `GET /api/v1/tariffs/box` (короба), `GET /api/v1/tariffs/commission` (комиссия по родительским категориям по модели продаж), `GET /api/v1/tariffs/pallet` (монопаллеты), `GET /api/v1/tariffs/return` (возвраты); комиссию можно получать токеном любой категории; лимит - 1 запрос в минуту (Wildberries, openapi.wildberries.ru/tariffs, дата неизвестна, https://openapi.wildberries.ru/tariffs/api/en/, сниппет, доступ 2026-09-02). То есть источник тарифов для оценки «до факта» - API, а не ручные таблицы; но подтверждение с самой страницы dev.wildberries.ru получить не удалось.

### Методология сверки с еженедельным финотчётом и ловушки

SelSup описывает 10-шаговую сверку: одна неделя; проверить тип отчёта (основной vs выкуп); зафиксировать номер отчёта/юрлицо/период/валюту; нормализовать знаки; проверить «Продажа» = реализовано минус возвраты; проверить «К перечислению» по детальному полю без двойного вычета; разнести расходы (логистика, хранение, приёмка, штрафы, удержания, кешбэк, корректировки); раскрыть «Прочие удержания» по основанию/сумме/номеру документа; свести сводку с деталкой в три колонки (сумма WB / свой расчёт / расхождение); объяснить остаток и проверить отдельные отчёты по хранению и приёмке (SelSup, 2024-02-11, обновлено 2026-07-24, https://selsup.ru/blog/finansovy-otchet-wildberries/, доступ 2026-09-02). Ключевая ловушка дословно: «Комиссию вычли дважды. Она уже учтена в поле «К перечислению Продавцу»» (там же). Другие ловушки: возвраты попадают в другие недели (временные расхождения); детализация хранения - отдельный отчёт; «Прочие удержания» непрозрачны без раскрытия; сравнение с банковской выпиской «день в день» игнорирует лаг выплаты; путать «Итого к оплате» с прибылью (там же). SelSup описывает свой расчёт прибыли так: «к данным площадки добавляют закупочную себестоимость, рекламу, налоги, зарплату сотрудников, упаковку, внешнюю доставку», хранит «исходные строки, правила распределения», но НЕ заявляет точность «до копейки» (там же).

Свидетельства пользователей о расхождениях: «Разница между аналитикой и финансовым отчётом Wildberries - основная боль растущего селлера, и разница может быть в сто рублей или в десятки тысяч»; типичная «ложная аналитика» - смотрят продажи по карточкам, а потом «из-за возвратов и удержаний прибыль испарилась» (TotalCRM, 2025-12, https://totalcrm.ru/blog/2025/12/ne-shoditsya-otchet-wildberries-poshagovyj-algoritm-poiska-rashozhdenij-i-spornyh-summ_78, сниппет, доступ 2026-09-02). Ни один прочитанный источник не заявляет «сходится до копейки» - ни вендоры, ни пользователи; единственная числовая метрика точности - маркетинговая «Точность данных более 95,3%» у Маяка без указания базы расчёта (Маяк, дата неизвестна, https://mayak.bz/, доступ 2026-09-02).

Отдельно про рекламу и налоги: методика Kassy.Center добавляет рекламу отдельным шагом после агрегации финотчёта, что подразумевает риск двойного счёта, если реклама уже удержана в `deduction`/«Прочие удержания» финотчёта - в прочитанных источниках это явно не разобрано (наблюдение, не факт из источника). MPSTATS в статье о юнит-экономике перечисляет компоненты: закупка/упаковка/доставка, комиссия площадки, логистика, хранение, эквайринг, реклама, доля возвратов, «прибыль после уплаты налогов» (MPSTATS, 2025-03-31, https://mpstats.io/media/business/finance/unit-ekonomika-dlya-marketpleisov, доступ 2026-09-02); о механике собственного модуля (источники данных, API) статья не говорит - лишь упоминает «бесплатный Онлайн-калькулятор юнит-экономики» (там же).

### Кто из RU-сервисов даёт P&L по SKU и почём

- Kassy.Center (mp.kassy.center): отчёты по юнит-экономике и P&L «какие товары зарабатывают, а какие нет», подключение WB по API (Kassy.Center, https://kassy.center/blog/unit-ekonomika-wildberries/, сниппет, доступ 2026-09-02). Цена не найдена.
- ReStata.ru: «автоматически сводит все данные и считает чистую прибыль по каждому SKU», без ограничений на число кабинетов (vc.ru, автор hager, дата неизвестна, https://vc.ru/id5622162/2769922-ocifrovka-prodazh-na-wildberries-kak-servis-restataru-pomogaet-selleram-videt-realnuyu-pribyl, сниппет, доступ 2026-09-02) - рекламный регистр, низкая уверенность.
- РНП «Рука на пульсе» (mpump.pro): P&L по группам и рекламные метрики (mpump.pro, сниппет, доступ 2026-09-02).
- Маяк: три тарифа - «Быстрый старт» 45 000 ₽/3 мес (15 000 ₽/мес), «Уверенный рост» 59 000 ₽/6 мес (~9 834 ₽/мес), «Доминирование» 98 000 ₽/12 мес (~8 167 ₽/мес); модуль «Юнит-экономика» «рассчитает прибыльность любого выбранного товара» во всех тарифах; про источник данных (финотчёт API) и про клиентские отчёты на странице ничего нет (Маяк, https://mayak.bz/, доступ 2026-09-02).
- MPSTATS: тариф «Весь Wildberries» «порядка 30 000 ₽/мес»; внутри «юнит-экономика, ROI, маржа, управление рекламой» (Uniseller, 2026, https://uniseller.io/blog/mpstats-obzor-servisa-analitiki-marketpleysov-2026/, сниппет, доступ 2026-09-02) - вторичный источник; официальная страница тарифов wiki.mpstats.io отдала только заголовок без контента.
- Sirena AI, JVO, Moneyplace: в этом раунде не прочитаны (см. «Не нашёл»).

### Клиентская отчётность агентств

RU-практика: еженедельный отчёт по каждому SKU должен включать показы, клики, конверсию в корзину, конверсию в заказ, процент выкупа; еженедельно - выручка, прибыльность, динамика категории, ежедневно - остатки и ставки рекламы (career.hh.ru, дата неизвестна, https://career.hh.ru/article/analitika-marketplejsov-klyuchevye-pokazateli-prodazh, сниппет, доступ 2026-09-02). Набор из 10 KPI отдела маркетплейсов: маржа после всех комиссий, ROMI, доля рекламных расходов с поправкой на выкуп, доля рекламных продаж, выкуп по категориям, индекс запасов, упущенные покупки, штрафы, SLA по задачам, скорость реакции на алерты (vc.ru, 2026, https://vc.ru/marketplace/2891530-kpi-otdela-marketpleysov-kak-upravlyat-pribylyu, сниппет; при прямом запросе страница отдала 404, доступ 2026-09-02). Агентства «обычно дают еженедельный P&L как часть процесса» (TotalCRM, https://totalcrm.ru/blog/otchety-prodazh-na-marketpleysakh-instruktsii-kejsy-sovety/, сниппет, доступ 2026-09-02) - без деталей формата «что сделали → эффект → план».

Глобальные инструменты брендированных отчётов: Sellerboard для агентств - «Export and automatically send predefined reports based on key KPIs - delivered to your email or synced to your spreadsheets on a regular schedule», «Add your agency's logo to the sellerboard dashboard», единый профиль агентства для всех клиентов, права доступа для конфиденциальности; ценовые уровни $15-$63/мес при годовой оплате ($19-$79 помесячно), Standard - 4 аккаунта/1 пользователь, Enterprise - 16 аккаунтов/4 пользователя (Sellerboard, https://sellerboard.com/agencies, дата неизвестна, доступ 2026-09-02). Triple Whale: агентства «can break out reporting by client», агенты-отчёты строятся одним запросом по всем бизнесам с разбивкой по бизнесу (Triple Whale Help Center, https://kb.triplewhale.com/en/articles/11554323-multi-business-reporting-with-business-breakdown, сниппет, доступ 2026-09-02); кейс DTC SEO Agency - «boosted client retention by 50%», алерты по изменениям органической выручки/трафика (Triple Whale blog, https://www.triplewhale.com/blog/dtc-seo-agency, сниппет, маркетинговый регистр). DataHawk в этом раунде не найден. Прямых свидетельств «какие элементы отчёта клиенты ценят» (опросы, ретроспективы) не найдено - только косвенное: единственная зафиксированная в Sellerboard отзыв-цитата про ценность - «The accuracy and completeness of Amazon data are unmatched» (Julian Herrlich, Namox, на sellerboard.com/agencies).

## Лиды для следующего раунда

- ПРИОРИТЕТ (противоречие): сводка поиска утверждала, что `GET /api/v5/supplier/reportDetailByPeriod` «объявлен к отключению 15.07.2026», но прочитанная страница Kassy.Center этого не содержит, а dev.wildberries.ru недоступен (498). Проверить через https://dev.wildberries.ru/en/release-notes и https://dev.wildberries.ru/en/news/82 (сниппеты в выдаче), либо через SDK-репозитории (pypi wildberries-sdk 0.1.147, github topic wildberries-api) - если отключение реально, вся ступень сверки зависит от нового метода.
- Официальная документация tariffs и financial-reports: попробовать зеркала `openapi.wildberries.ru/tariffs/api/en/` (в выдаче есть), `dev.wildberries.ru/en/docs/openapi/wb-tariffs` (en-версия может не давать 498), SDK-репозитории на GitHub.
- Двойной счёт рекламы: ни один источник явно не объяснил, попадает ли рекламный расход в `deduction`/«Прочие удержания» финотчёта и как его отделять от данных adv-API. Нужен источник с формулой (TotalCRM «не сходится отчёт», allo.tochka.com/finotchet-wb, uniseller «как читать финотчёты»).
- Не покрыты вендоры: Sirena AI, JVO, Moneyplace, MPStats (официальные тарифы - wiki отдала пустую страницу), Sellerboard-подобные RU (ReStata, Kassy.Center - цены). Также DataHawk (agency reports) не найден.
- Свидетельства ценности элементов отчёта для клиентов агентств: искать кейсы/ретроспективы агентств (sholchev.ru в выдаче), Sellerboard/Triple Whale отзывы агентств с production-числами, а не маркетинг.
- Маяк «точность 95,3%» - выяснить базу метрики (это про внешнюю аналитику продаж, а не про сверку с финотчётом?).
- Storage attribution: SelSup указывает, что хранение - отдельный отчёт; проверить, есть ли в API метод отчёта по платному хранению по SKU (paid_storage) и как вендоры разносят его на SKU.

## Не нашёл

- Официальный текст документации WB по reportDetailByPeriod и tariffs (HTTP 498 на dev.wildberries.ru) - только сторонние пересказы и сниппеты.
- Ни одного вендора, заявляющего «сходится до копейки» с финотчётом; ни одного пользовательского отчёта с числами точности сверки (в рублях/процентах).
