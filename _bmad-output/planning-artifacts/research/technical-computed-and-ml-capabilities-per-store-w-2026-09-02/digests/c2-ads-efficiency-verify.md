# c2-ads-efficiency - отчёт независимой верификации

Дата проверки: 2026-09-02. Уровень: normal (spot-check только load-bearing claims из r1/r2). Все URL ниже - доступ 2026-09-02.

## Условия раунда

- Сессионный лимит WebSearch исчерпан (200/200) до начала проверки - четыре поисковых запроса не выполнились. Независимые издатели добирались только прямыми запросами (WebFetch / curl по известным URL).
- Официальные страницы WB по-прежнему недоступны: `https://dev.wildberries.ru/en/news/297` - HTTP 498. Первичная спецификация получена через зеркало OpenAPI в репозитории eslazarev/wildberries-sdk (raw `specs/08-promotion.yaml`, 270 721 байт; `specs/11-analytics.yaml`, 290 441 байт). Это другой издатель, но те же исходные данные (копия спецификации WB) - для API-claims принято как первичка с пометкой «зеркало».
- Каталоги/обзоры для второго источника по ценам Marketguru: startpack.ru - 403, otzyvmarketing.ru - соединение не установлено, wbstat.pro/blog/marketguru - 404, sellerdata.ru - 404.
- Бюджет: 12 tool calls на исследование превышен на один (13) из-за неудачного пакета ugrep; отчёт - отдельный вызов.

## Результаты по претензиям

### 1. `GET /adv/v3/fullstats` - статистика кампаний любого типа, максимум 31 день - VERIFIED

Спецификация `specs/08-promotion.yaml`, путь `/adv/v3/fullstats` (строка 3317), сервер `https://advert-api.wildberries.ru`, summary «Статистика кампаний», description дословно: «Метод формирует статистику для кампаний независимо от типа. … Максимальный период в запросе — 31 день.» Дополнительно из той же спецификации: параметр `ids` - «ID кампаний, максимум 50 значений»; лимит запросов - 3 запроса/мин (интервал 20 с, всплеск 1) для персонального/сервисного/базового-с-секретом токенов, 1 запрос/час для базового; в песочнице статистика за 30 дней. Источник: eslazarev/wildberries-sdk (GitHub, зеркало OpenAPI WB), обновлён 2026-09-02, https://raw.githubusercontent.com/eslazarev/wildberries-sdk/main/specs/08-promotion.yaml. Оговорка: издатель другой, исходные данные те же (копия спецификации WB); второго независимого набора данных для API-claim не существует по определению.

### 2. `SEARCH_QUERIES_PREMIUM_REPORT_GROUP/TEXT` - 365 дней, только «Джем»; `price` и `medianPosition` в «Поисковые запросы по товару» - VERIFIED (частично)

Подтверждено спецификацией `specs/11-analytics.yaml` (тот же источник, https://raw.githubusercontent.com/eslazarev/wildberries-sdk/main/specs/11-analytics.yaml): типы отчётов `SEARCH_QUERIES_PREMIUM_REPORT_GROUP`, `SEARCH_QUERIES_PREMIUM_REPORT_PRODUCT` (в дайджесте не упомянут), `SEARCH_QUERIES_PREMIUM_REPORT_TEXT` (строки 327-329); «Можно получить отчёт максимум за последние 365 дней» (строки 73, 1223); параметры периода «Не ранее 365 суток от сегодня» (3225-3264); поле `MedianPosition` в CSV-отчёте `..._TEXT` и `medianPosition` в JSON-методе поисковых запросов (2856, 3011); в CSV-отчётах цена представлена полями `MinPrice`/`MaxPrice`, не `price`. Не подтверждено грепом: формулировка «только с подпиской Джем» для именно этих типов отчётов - в спецификации явное «только с подпиской Джем» найдено для `DETAIL_HISTORY_REPORT`/`GROUPED_HISTORY_REPORT` (строки 150, 219), а для поисковых запросов Джем упоминается как повышающий лимит `limit` до 100 на тарифах «Продвинутый»/«Премиальный» (1147, 3034). Первоисточник claim (dev.wildberries.ru/en/news/297) недоступен (HTTP 498). Вывод: срок 365 дней и `medianPosition` подтверждены, «только Джем» и имя поля `price` - остаются на уровне сниппета.

### 3. Пороги слива Uniseller (ДРР >25%, 15-25% ждать 2-3 недели, 0 заказов 7-14 дней, 30-40% бюджета на нерелевантные, SKU-идеал 8-10%) - UNVERIFIED

Первичная страница прочитана (curl, HTTP 200) и подтверждает текст: «Если ДРР выше 25 % и товар не на старте — либо снижайте ставки, либо отключайте продвижение», «Если ДРР 15–25 % и товар на этапе роста — следите за динамикой. Если за 2–3 недели ДРР не снижается, пересмотрите семантику», «отключите всё, что не приносит заказов дольше 7–14 дней», «Если 30–40 % бюджета уходит на нерелевантные запросы … Соберите минус-слова» (Uniseller, 24.07.2026, обновлено 18.08.2026, https://uniseller.io/blog/audit-reklamy-wildberries-kak-ne-slivat-byudzhet-i-kontrolirovat-drr/). Расхождение с дайджестом: формулировки «SKU-идеал 8-10%» на странице нет - там «Если кампания показывает ДРР 8–10 % при целевом 15 %, вы можете смело повышать ставки» (правило масштабирования, не «идеал SKU»). Понижающие флаги: в подвале статьи - «Эта статья подготовлена с помощью ИИ на основе открытых источников. Возможны неточности», источник указан как mpmgr.ru (23.07.2026) - то есть это производный текст неназванного происхождения. Независимое подтверждение (MGUTU) получить не удалось: страница https://mgutu.ru/media/business/reklama-na-wildberries/ отдала HTTP 200, но без текстового контента (16 КБ, JS-шаблон); поиск недоступен. Статус: пороги воспроизведены точно (кроме «8-10%»), но остаются редакционными числами одного ИИ-сгенерированного источника.

### 4. Amazon-референс Seller Labs (break-even ACoS, порог $35 / клики 2-3×(1/CR), Negate/Throttle/Harvest) - VERIFIED

Первичная страница подтверждает дословно: «(Sale Price − COGS − Amazon Fees) ÷ Sale Price = Break-Even ACoS» (пример $12/$35 = 34%); «$35 in spend with zero conversions» как «industry baseline», корректируемый по цене; клики - «how many clicks you need for one sale. Multiply by 2-3x» (пример CR 10% → 20-30 кликов); Tier 1 Negate - порог превышен без конверсий или явная нерелевантность → exact-match negative; Tier 2 Throttle - «Spent 50-100% of your threshold with zero conversions» → ставка к break-even ACoS, пересмотр через месяц; Tier 3 Harvest - «2+ conversions at an ACoS below your break-even» → exact-match кампания (Seller Labs, 2026-03-23, https://www.sellerlabs.com/blog/amazon-ppc-audit-system-monthly-wasted-ad-spend/). Атрибуция и содержание claim точны. Оговорка: независимый второй издатель для «$35 - индустриальный стандарт» не получен (поиск недоступен); формула break-even ACoS - общепринятая арифметика маржи, но это моё предположение, не доказательство из этого прогона.

### 5. Marketguru Биддер - пересчёт каждые 2 минуты, исключение ключей, дневной лимит, автопополнение, out-of-stock, история изменений, без approve, триал 4 дня - VERIFIED (с поправками)

Живая страница подтверждает: «Каждые 2 минуты автобиддер пересматривает рекламные ставки»; «Исключение слабых фраз по CTR, CPC, ДРР, заказам»; «Контроль дневного лимита, ставок и расхода»; «Автопополнение по правилам»; «Защита при out-of-stock — без слива бюджета»; «История изменений — полная прозрачность»; «4 дня бесплатно» с неограниченным доступом (Marketguru, дата неизвестна, https://marketguru.io/tools/bidder). Поправки к дайджесту: критерии исключения - CTR/CPC/ДРР/заказы, а не «CTR/CPC/ROI»; утверждение «без человеческого approve» на странице явно не сформулировано - это вывод из отсутствия упоминания approve-флоу, а не заявление вендора. Независимый издатель (обзор/отзывы) не получен. Класс pattern - один первичный источник допустим.

### 6-7. Тарифы Marketguru (4 990 / 19 990 / 29 990 ₽/мес; биддер 10/50/200 кампаний; репрайсер 50/250/1000; скидки 10/15/20%; расширение 990 ₽/мес; холдинг по заявке) - UNVERIFIED (по правилу двух источников для pricing)

Живая страница тарифов подтверждает все числа обеих формулировок дословно: «Малый бизнес» 4 990 ₽/мес - 1 API-ключ, «Биддер: 10 рекламных кампаний», «Репрайсер: 50 товаров», автоответы 500/мес, «Оракул AI: 100 токенов/мес»; «Средний бизнес» 19 990 ₽/мес - 2 ключа, биддер 50, репрайсер 250, автоответы 2000, Оракул 250; «Крупный бизнес» 29 990 ₽/мес - 5 ключей, биддер 200, репрайсер 1000, автоответы 5000, Оракул 1000; скидки 3/6/12 мес - 10/15/20%; «Расширение для Wildberries» - «990 ₽ / в мес.»; «Индивидуальный холдинг» - индивидуально, «Безлимиты по товарам, кампаниям и SEO-генерациям»; триал на странице тарифов не упомянут (Marketguru, дата неизвестна, https://marketguru.io/prices). Второй независимый издатель не получен (поиск недоступен; четыре каталога - 403/404/нет соединения). Ранее зафиксированное расхождение «от 9 900 ₽» (Uniseller, 30.08.2026, по r1) в этом прогоне не перепроверялось. По карте качества источников pricing требует двух независимых издателей - статус остаётся unverified, хотя первичная страница подтверждена целиком; при использовании цитировать как «живая страница, доступ 2026-09-02».
