# c2-ads-efficiency - round 1

Дата доступа ко всем источникам: 2026-09-02. Бюджет: 18 tool calls исчерпан; прочитано 8 страниц (2 официальные страницы WB API не открылись).

## Что искал и что нашёл

### Официальная read-only поверхность WB Promotion API

Официальная документация закрыта для инструмента: `https://dev.wildberries.ru/en/docs/openapi/promotion` вернула HTTP 498, `https://openapi.wildberries.ru/promotion/api/ru/` - «proxy refused the connection» (доступ 2026-09-02); поэтому факты об API ниже - из поисковых сниппетов и community-кода, уверенность понижена. По сниппету документации, метод `GET https://advert-api.wildberries.ru/adv/v3/fullstats` «генерирует статистику кампаний независимо от их типа», максимальный период в запросе - 31 день (Wildberries, openapi.wildberries.ru, дата неизвестна, https://openapi.wildberries.ru/promotion/api/ru/, сниппет поиска, доступ 2026-09-02). Community-скрипт для выгрузки статистики использует предыдущую версию `POST https://advert-api.wb.ru/adv/v2/fullstats`, разбирает массив `days` в ответе, ссылается на `adv/v1/promotion/adverts` (даты старта кампаний) и `adv/v1/promotion/count` (список ID кампаний), при ошибке 400 сдвигает дату старта на день и повторяет запрос, а при не-200 спит 60 с; в комментариях (октябрь 2024) пользователь спрашивает, как выгрузить статистику по номенклатуре, а не по кампании - то есть разрез «по артикулу внутри кампании» не очевиден из выдачи (MikyPo, GitHub Gist, обновлён 2025-01-19, https://gist.github.com/MikyPo/92c75351197e06bd6c85ba4825a10750, доступ 2026-09-02). Состав кластера (список запросов) доступен в статистике автоматической кампании в блоке «Ключевые фразы» (vc.ru, дата неизвестна, https://vc.ru/marketplace/1689017-klastery-zaprosov-na-wildberries-chto-eto-takoe-i-kak-s-nimi-rabotat, сниппет, доступ 2026-09-02). Смежная поверхность из Analytics API: отчёты поисковых запросов `SEARCH_QUERIES_PREMIUM_REPORT_GROUP` и `SEARCH_QUERIES_PREMIUM_REPORT_TEXT`, данные доступны максимум за 365 дней и только с подпиской «Джем»; в метод «Поисковые запросы по товару» добавлены поля `price` и `medianPosition` (Wildberries, dev.wildberries.ru/en/news/297, дата неизвестна, сниппет, доступ 2026-09-02). Отдельный эндпоинт нормализованных запросов (normquery stats) для рекламы найти по сниппетам не удалось - см. «Не нашёл».

Что WB не даёт готовым: «Wildberries не показывает ДРР в готовом виде», данные нужно собирать из нескольких разделов кабинета вручную, что создаёт риск расхождений между рекламными отчётами и финансовыми (Uniseller, 2026-07-24, обновлено 2026-08-18, https://uniseller.io/blog/audit-reklamy-wildberries-kak-ne-slivat-byudzhet-i-kontrolirovat-drr/, доступ 2026-09-02).

### Правила детекции «слива бюджета» на WB (RU-источники)

Единственный найденный в этом раунде набор явных числовых порогов для WB - редакционный (Uniseller, 2026-07-24/2026-08-18, URL выше): ДРР выше 25% вне фазы запуска - снижать ставки или отключать продвижение; ДРР 15-25% в фазе роста - наблюдать 2-3 недели, пересматривать при отсутствии улучшений; ноль заказов за 7-14 дней - отключать сразу; 30-40% бюджета на нерелевантные запросы - вводить минус-фразы; на уровне SKU идеал 8-10%, проблема от 25%. Тот же источник рекомендует считать ДРР двумя способами - по атрибуции (расход на рекламу / выручка от рекламы) и по общему обороту магазина - и обязательно учитывать возвраты: игнорирование возвратов искажает ДРР на 3-5 п.п., в одежде с возвратами 50-60% - сильнее. Порог «ДРР выше 25% и товар не на старте - снижать ставки или отключать» повторяет и MGUTU (mgutu.ru, дата неизвестна, https://mgutu.ru/media/business/reklama-na-wildberries/, сниппет, доступ 2026-09-02) - вероятно, единый источник, не независимое подтверждение.

### Методология Amazon PPC (референс)

Seller Labs описывает месячный аудит поисковых терминов: break-even ACoS = (цена − COGS − комиссии Amazon) / цена; порог минусации - «$35 расхода без конверсий» (индустриальный стандарт, корректируется по цене товара) либо клики = 2-3 × (1/CR); три уровня действий - Negate (порог превышен без конверсий или явно нерелевантно → exact-match negative), Throttle (50-100% порога без конверсий → снизить ставку до break-even ACoS, пересмотр через месяц), Harvest (2+ конверсии при ACoS ниже порога → перенос в exact-match кампанию); guardrails - «irrelevance override», требование «больше данных» перед понижением, и предупреждение, что Amazon хранит Search Term Report ~60-65 дней, поэтому нужны ежемесячные выгрузки; оценка потерь - «28-40% месячного бюджета» на неконвертирующие термины, кейс «$10,625 за 60 дней - 40% бюджета» (Seller Labs, 2026-03-23, https://www.sellerlabs.com/blog/amazon-ppc-audit-system-monthly-wasted-ad-spend/, доступ 2026-09-02; цифры потерь - маркетинговый регистр, низкая уверенность). По сниппетам, Optmyzr и Helium 10 реализуют то же как правила: блокировать ключи/ASIN, не конвертирующие после N кликов; искать термины с высоким расходом без конверсий и предлагать их в negatives; алерты при перерасходе и авто-пауза/коррекция ставок при пересечении порога (Optmyzr, дата неизвестна, https://www.optmyzr.com/blog/amazon-audit/; Helium 10, дата неизвестна, https://www.helium10.com/blog/reclaim-20-hours-per-week-how-to-automate-amazon-ppc-management/; сниппеты, доступ 2026-09-02).

### Guardrails и режим действий у RU-поставщиков

Marketguru «Биддер»: полностью автоматический режим - пересчёт ставок каждые 2 минуты, «удержание позиции минимальной ставкой», исключение неэффективных ключевых слов по CTR/CPC/ROI, дневной лимит бюджета, автопополнение по правилам пользователя, защита от рекламы out-of-stock; прозрачность через историю изменений, без человеческого approve; пробный доступ 4 дня (Marketguru, страница без даты, реестр ПО 11.06.2025, https://marketguru.io/tools/bidder, доступ 2026-09-02). MPfact, напротив, работает как рекомендательный слой: собирает через WB API статистику авто- и аукционных кампаний с ежедневным обновлением, метрики - показы, клики, CTR, CPM, конверсия в корзину/заказ, расход, CPC, CPO, ДРР; разрезы бренд/товар/кампания/платформа (iOS/Android/Web)/статус/магазин/категория до SKU; проблемные зоны подсвечиваются цветом, выдаются рекомендации «какие кампании отключить», без автоматических действий; окно атрибуции и методика подсчёта заказов не раскрыты; 4 дня триала без карты (MPfact, дата неизвестна, https://mpfact.ru/analitica-reclama-wb, доступ 2026-09-02). helpexcel.pro (шаблон на официальном API): показы, клики, CR, заказы, «СУММА ЗАТРАТ по рекламной кампании» по артикулам и по платформам (PC/iOS/Android), обновление ежедневно, предупреждение «Проект лучше связывать с базой данных» из-за объёма данных (helpexcel.pro, дата неизвестна, https://www.helpexcel.pro/rkwb, доступ 2026-09-02). По сниппетам: Aurum Sky - ИИ управляет ставками по целям «удержание ДРР или рентабельности, план по заказам в штуках/рублях, удержание выдачи и оборачиваемости», 7 дней триала (aurum-sky.net, дата неизвестна, https://aurum-sky.net/adv, сниппет, доступ 2026-09-02); Stat4Market - биддер с автоматическим управлением ставками (stat4market.com, дата неизвестна, https://stat4market.com/wb-analytics/bidder/, сниппет, доступ 2026-09-02).

### Что говорят пользователи о точности

Прямых пользовательских отзывов про двойной учёт «статистика кампании vs финансовый отчёт» или про окно атрибуции найти не удалось: поиск дал только поставщиков (MPFINASSIST, MPfact, totalcrm) без конкретики. Косвенно проблема признаётся редакцией Uniseller (ДРР не даётся готовым, сбор из разных разделов, риск расхождений) и community-кодом (выгрузка по кампании, а не по номенклатуре). Ни один из прочитанных поставщиков (MPfact, helpexcel, Marketguru) не раскрывает окно атрибуции и способ подсчёта заказов.

## Лиды для следующего раунда

- Противоречие (приоритет): цена Marketguru - 4 990 ₽/мес на marketguru.io/prices против «от 9 900 ₽» в обзоре Uniseller (2026-08-30); проверить, не относится ли 4 990 к тарифу без биддера или к акции.
- Официальная документация WB Promotion API недоступна через WebFetch (498/proxy). Альтернативы: SDK-репозитории на GitHub (поиск `adv/v3/fullstats` в коде), зеркала документации, Postman-коллекции; уточнить состав полей `fullstats` (views, clicks, ctr, cpc, sum, atbs, orders, shks, sum_price, canceled), разрез по `nmId` внутри `days`, лаг данных и лимиты запросов.
- Эндпоинт статистики нормализованных запросов/кластеров (`/adv/v0/stats/keywords`, «normquery», «Ключевые фразы» в автокампаниях) - не подтверждён; искать в SDK/новостях dev.wildberries.ru/news.
- Пользовательский голос: искать на vc.ru, Habr, Telegram-каналах и форумах запросы вида «fullstats расходится с отчётом о реализации», «атрибуция заказов в рекламе WB», «двойной учёт заказов авто и аукцион»; в этом раунде найдены только страницы поставщиков.
- Поставщики без прочитанных первичных страниц: MPSTATS (tariffs пустая), Маяк, JVO, WBStat, Anabar, LikeStats, Stat4Market, Aurum Sky, MPFINASSIST, Fullstats (сервис на VK) - прочитать их страницы «реклама/биддер» и цены.
- Методика оценки экономии у RU-поставщиков: FullStats обещает «до 40% экономии бюджета» (сниппет VK) - выяснить, как считают; у Seller Labs «28-40%» - тоже без методики.
- Guardrails: у Marketguru - автоматика без approve; у MPfact - только рекомендации. Проверить, есть ли у кого-то промежуточный режим (предложение → подтверждение → действие) и «сухой прогон».
- Правило «реклама на товаре без остатка»: подтверждено только как фича Marketguru; проверить, даёт ли WB API остатки по складам в связке с `nmId` кампании (Statistics/Marketplace API) для read-only детектора.

## Не нашёл

- Первичную документацию WB Promotion API (fullstats v3, лимиты, лаг, поля ответа, статистика по ключевым фразам/нормализованным запросам) - обе официальные страницы недоступны инструменту.
- Пользовательские отзывы/треды о двойном учёте между статистикой кампаний и финансовым отчётом и об окне атрибуции WB - поиск дал только страницы поставщиков.
- Актуальные цены MPSTATS, Маяк, JVO, WBStat, Anabar с живых страниц (только агрегатор Uniseller; mpstats.io/tariffs открылась без контента).
- Публичную методику расчёта «сэкономленного бюджета» у RU-поставщиков и у Amazon-инструментов.
- Правила SKU-каннибализации (одна карточка в нескольких кампаниях / автокампания vs аукцион) - ни у одного источника.
