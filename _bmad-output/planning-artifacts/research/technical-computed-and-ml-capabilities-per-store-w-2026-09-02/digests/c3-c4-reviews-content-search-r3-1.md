# c3-c4-reviews-content-search - round 3

Дата доступа ко всем источникам: 2026-09-02. Ограничение раунда: бюджет WebSearch сессии был исчерпан (200/200) до старта, поэтому все данные получены только через WebFetch прямых URL; DuckDuckGo отдал CAPTCHA, Bing - нерелевантную выдачу (литовская локаль), то есть «поисковые» лиды (цена Джем, история изменений карточки, политики 152-ФЗ, эмпирика рейтинг→конверсия) закрыть не удалось.

## Что искал и что нашёл

### Противоречие по году нативного ИИ-ответчика WB - решено в пользу 2026
Поиск по превью канала (`t.me/s/rwb_press_service?q=отзывы`) показывает пост `t.me/rwb_press_service/1347` с датой 2026-02-19: «нейросеть не только поможет составить ответы покупателям, но и даст возможность настроить их для автоматической отправки» (Telegram, Пресс-служба RWB, 2026-02-19, https://t.me/rwb_press_service/1347, доступ 2026-09-02). Прямая выборка embed-версии того же поста через WebFetch вернула дату «February 19, 2025» - расхождение на год между двумя рендерами одной страницы (Telegram, https://t.me/rwb_press_service/1347?embed=1, доступ 2026-09-02). Расхождение снимается монотонностью ID постов: пост 907 датирован 2025-05-30, 1044 - 2025-07-31, 1138 - 2025-09-22, значит пост 1347 не может быть февралём 2025 и относится к 2026-02-19 (Telegram, https://t.me/s/rwb_press_service?q=отзывы, доступ 2026-09-02). Содержание поста: после настройки параметров «дальнейшая работа происходит автоматически с помощью ИИ», система может «самостоятельно генерировать и сразу же публиковать ответ», учится на прежних ответах продавца, может рекомендовать товары, и не отвечает при недостатке данных в карточке - такие отзывы остаются на ручную обработку (Telegram, Пресс-служба RWB, 2026-02-19, https://t.me/rwb_press_service/1347?embed=1, доступ 2026-09-02). В посте не указано, бесплатна ли функция и входит ли она в Джем, не назван и LLM (там же). Вывод для C3: у WB есть нативный режим «черновик + опциональная автопубликация», поэтому третий сервис конкурирует не с отсутствием функции, а с бесплатным (не подтверждено) встроенным.

Смежная хронология ИИ-фич WB по отзывам из того же превью канала: 2026-01-22 (/1302) «Важное из отзывов» - «нейросеть, которая кратко пересказывает содержание отзывов» выведена в широкое тестирование; 2026-02-17 (/1341) ИИ-фильтры отзывов - «ML-модель, которая анализирует тексты отзывов, определяет ключевые темы»; 2026-04-06 (/1399) ключевые характеристики из отзывов в поисковой выдаче; 2026-07-06 (/1595) метка «Похоже на ИИ» на обработанных ИИ фото в отзывах; 2026-08-21 (/1723) обновление «Умного сравнения» с блоком «Важное из отзывов» на BerryLM (Telegram, Пресс-служба RWB, https://t.me/s/rwb_press_service?q=отзывы, доступ 2026-09-02). Пост 2026-06-25 (/1578): BerryLM-XL в топ-3 бенчмарка MERA с 0.835, «совокупный эффект от применения ИИ-инструментов составляет более 1 млрд рублей дополнительной выручки» - маркетинговая цифра без методики (там же).

### Официальная поверхность отзывов/вопросов - спецификация 09-communications.yaml
Спека SDK eslazarev/wildberries-sdk (`specs/09-communications.yaml`, заголовок «Общение с покупателями», base URL `https://feedbacks-api.wildberries.ru`, sandbox `feedbacks-api-sandbox.wildberries.ru`) перечисляет: `GET /api/v1/new-feedbacks-questions`, `GET /api/v1/questions/count-unanswered`, `GET /api/v1/questions/count`, `GET|PATCH /api/v1/questions`, `GET /api/v1/question`, `GET /api/v1/feedbacks/count-unanswered`, `GET /api/v1/feedbacks/count`, `GET /api/v1/feedbacks`, `POST|PATCH /api/v1/feedbacks/answer`, `POST /api/v1/feedbacks/order/return`, `GET /api/v1/feedback`, `GET /api/v1/feedbacks/archive`, плюс закрепление отзывов `/api/feedbacks/v1/pins` (GET/POST/DELETE), `/pins/count`, `/pins/limits` («лимиты закрепления по подписке/тарифу») и чат с покупателем `GET /api/v1/seller/chats`, `GET /api/v1/seller/events` на `https://buyer-chat-api.wildberries.ru` (GitHub eslazarev/wildberries-sdk, дата спеки unknown, https://raw.githubusercontent.com/eslazarev/wildberries-sdk/main/specs/09-communications.yaml, доступ 2026-09-02).

Объект отзыва содержит `id`, `text`, `productValuation`, `createdDate`, `userName`, `answer{text,state,editable}`, `productDetails{nmId,imtId,productName,supplierArticle,supplierName,brandName,size}`, `photoLinks[{fullSize,miniSize}]`, `video{previewImage,link,durationSec}`, `state`, `wasViewed`, `pros`, `cons`, `matchingSize`, `orderStatus`, `isAbleSupplierFeedbackValuation`, `supplierFeedbackValuation`, `isAbleSupplierProductValuation`, `supplierProductValuation`, `isAbleReturnProductOrders`, `returnProductOrdersDate`, `bables`, `lastOrderShkId`, `lastOrderCreatedAt`, `color`, `subjectId`, `subjectName`, `parentFeedbackId`, `childFeedbackId`; объект вопроса - `id`, `text`, `createdDate`, `state`, `answer{text,editable,createDate}`, `productDetails{...}`, `wasViewed`, `isWarned` (там же). Для детектора событий важно: `createdDate`, `productValuation`, `state`, `wasViewed`, `answer` есть - этого достаточно для событий «новый негативный отзыв», «возраст без ответа», «падение среднего рейтинга по nmId» на своей стороне; `userName` - персональные данные покупателя, попадающие в любой LLM-промпт.

`GET /api/v1/feedbacks`: `isAnswered` (boolean, обязателен), `nmId`, `take` (обязателен, max 5 000), `skip` (обязателен, max 199 990), `order` (`dateAsc`|`dateDesc`), `dateFrom`/`dateTo` (unix timestamp) (там же). Лимиты категории «Вопросы и отзывы»: 3 запроса/с, интервал 333 мс, burst 6 для personal/service/basic-with-secret токенов; basic - 5 запросов/час; чаты - 10 запросов/10 с (там же). Правила состояния: «Отредактировать ответ можно только один раз в течение 60 дней c момента отправки»; отзыв считается обработанным, если получен ответ ИЛИ отзыв содержит только оценку без текста/фото; отзыв уходит в архив, если получен ответ, прошло 30+ дней без ответа, или это отзыв только с оценкой (там же). Следствие для SLA: официального события «падение рейтинга»/«SLA возраста» в API нет, но пороги детектора должны быть заведомо меньше 30 дней, иначе отзыв уйдёт в `/feedbacks/archive` до срабатывания. Задержка появления нового отзыва в API в спеке не указана (там же).

### Поисковая аналитика - спецификация 11-analytics.yaml
Группа `/api/v2/search-report/`: `POST /report` («Основная страница»), `POST /table/groups`, `POST /table/details`, `POST /product/search-texts` («Поисковые запросы по товару»), `POST /product/orders` («Заказы и позиции по поисковым запросам товара») (GitHub eslazarev/wildberries-sdk, https://raw.githubusercontent.com/eslazarev/wildberries-sdk/main/specs/11-analytics.yaml, доступ 2026-09-02). Параметры: `currentPeriod`, `pastPeriod`, `nmIds`, `subjectIds`, `brandNames`, `tagIds`, `positionCluster` (средняя позиция в поиске), `orderBy`, `includeSubstitutedSKUs`, `includeSearchTexts` (оба не могут быть `false`), `limit` (max 1000), `offset`; для `/product/search-texts` - `nmId`, `limit` («максимум — 30», «максимум — 100» для тарифов Джема Продвинутый и Премиальный), `topOrderBy`; для `/product/orders` - «максимальный период — 7 дней» (там же). Поля ответа: `frequency`/`weekFrequency`, `avgPosition`/`averagePosition`, `medianPosition`, `visibility` (вероятность показа, %), `openCard`, `addToCart`, `orders`, `cartToOrder`, `openToCart`, `openCardPercentile`/`addToCartPercentile`/`orderPercentile` (относительно конкурентов), `text`/`searchText`, по товарам `name`, `rating`, `minPrice`, `maxPrice`, `isAdvertised`, «Динамика по сравнению с предыдущим периодом, %» (там же). «Данные отчёта обновляются 1 раз в час», «Можно получить отчёт максимум за последние 365 дней»; лимит 3 запроса/мин, burst 3 (personal/service/basic+secret), basic - 1 запрос/час (там же).

Джем в спеке упоминается только в четырёх местах: `/api/analytics/v3/sales-funnel/products/history` и `/grouped/history` («Отчёты этого типа доступны только с подпиской [Джем](https://seller.wildberries.ru/monetization/jam)» - для периода до года через CSV `DETAIL_HISTORY_REPORT`/`GROUPED_HISTORY_REPORT`), `/api/v2/nm-report/downloads` (отчёты по остаткам «можно создать без подписки Джем») и `/api/v2/search-report/product/search-texts` (лимит 100 вместо 30 для тарифов Продвинутый/Премиальный, ссылка https://seller.wildberries.ru/monetization/tariffs) (там же). То есть по тексту спеки сами методы search-report Джем не требуют - расширяется только глубина топа запросов; это противоречит распространённому допущению «поисковая аналитика WB = только Джем» и нуждается в подтверждении официальной документацией/кабинетом (dev.wildberries.ru в этом и прошлых раундах не отдаётся). Существует также `POST /api/analytics/v2/item-rating` («Получить отчёт», датасет по рейтингам товаров, обновление 1 раз в час, 3 запроса/мин, только personal/service токены, без упоминания Джем) - потенциальный официальный источник для события «падение рейтинга»; поля `ItemRatingResponse` в усечённой выдаче не видны (там же). Спека также содержит `/api/analytics/v3/sales-funnel/products` (365 дней истории, «Most data appears within one hour of events»), `/api/analytics/v1/order-feed`, `/api/v2/stocks-report/...` (там же).

Репозиторий: 14 спек в `specs/` (`01-general` … `14-wbd`), документация https://eslazarev.github.io/wildberries-sdk/, 42 звезды, 492 коммита, «клиенты поддерживаются в актуальном состоянии с помощью GitHub Actions при обновлении спецификаций», изменения спецификаций «несколько раз в неделю» (GitHub eslazarev/wildberries-sdk, https://github.com/eslazarev/wildberries-sdk, доступ 2026-09-02). Дата последней синхронизации на странице не показана; спека - производная от OpenAPI WB, а не первичная документация, поэтому все «api»-claims ниже - medium.

### Связь рейтинга и продаж - только платформенные механики WB
Прямой эмпирики (A/B, до/после) по-прежнему нет; найдены механики самой платформы: бейдж «Выбор покупателей» выдаётся товарам с рейтингом 4.7+ и 40+ отзывов (Telegram, Пресс-служба RWB, 2025-07-31, https://t.me/rwb_press_service/1044, доступ 2026-09-02) - рейтинг влияет на видимость через бейдж, а не через доказанную конверсию. Исследование WB о качестве карточек: «лидирующие карточки» дают 43% намерения покупки в женской одежде - методика не раскрыта (Telegram, Пресс-служба RWB, 2026-05-07, https://t.me/rwb_press_service/1473, доступ 2026-09-02). Отчёт о двух годах Джема: 500 тыс. A/B-тестов (Telegram, Пресс-служба RWB, 2026-04-27, https://t.me/rwb_press_service/1462, доступ 2026-09-02).

Ни один провайдер автоответов в этом раунде не прочитан; раскрытий по месту исполнения LLM/трансграничной передаче нет. Второй источник цены Джем не получен (поисковые прокси не сработали); в спеке WB есть только ссылка на страницу тарифов `https://seller.wildberries.ru/monetization/tariffs` и названия тарифов Продвинутый/Премиальный. По алертам на изменение фото/описания карточки новых данных нет.
