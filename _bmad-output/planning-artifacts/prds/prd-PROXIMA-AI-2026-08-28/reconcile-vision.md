# Reconcile: PRODUCT-VISION vs PRD W1-срез

*Дата: 2026-08-28. Входы: `.planning/PRODUCT-VISION.md` (Approved 2026-08-16) и `_bmad-output/planning-artifacts/prds/prd-PROXIMA-AI-2026-08-28/prd.md` (draft).*

Метод: гэпом считается решение vision, которое ограничивает W1 и отсутствует или противоречит в PRD. Осознанные исключения W2-W4/M3 (сценарии W2-W4, SaaS, чат Q&A, PDF-генератор, автоисполнение, Ozon) гэпами не считаются.

**Вердикт: gaps found.** Скелет W1 совпадает (детекторы, квота, LLM-контур, Telegram critical, ритм 07:00, unreleased-маркировка, read-only), но 12 позиций vision либо выпали молча, либо противоречат PRD.

## Гэпы

### GAP-1. Источники данных W1 не перечислены (Statistics API + Advertising)
- **Vision:** раздел 4, таблица волн - «W1 (нед. 1-3): Statistics API (+ Advertising API подключаем как источник)»; строка «Данные (№31-38)» - «Advertising (сразу)».
- **PRD:** единственное упоминание источников - «W1 читает только WB» (раздел 2.2) и OQ-2 по поставкам. Ни Statistics, ни Advertising не названы. От этого зависит FR-6 («ожидаемые источники» для SCN-008 не определены) и реализуемость SCN-001/005.
- **Severity:** high.
- **Fix:** добавить в PRD раздел «Источники данных W1»: Statistics API - базовый, Advertising API - подключается в W1 по решению vision; либо явно supersede с датой и ссылкой на решение.

### GAP-2. Сдвиг V1-гейта и LLM в W1 против roadmap vision
- **Vision:** раздел 6, roadmap - LLM-диагнозы и «V1: первый сквозной сигнал» стоят в неделях 4-6 (W2); verification-петля - в неделях 7-10 (W3).
- **PRD:** раздел 1 и SM-1 - «Выход среза - V1 value gate» в W1; раздел 4.6 - LLM в W1; раздел 4.8 - verification в W1. PRD ускоряет план на 1-2 волны и нигде не оговаривает это как отклонение от утверждённого roadmap.
- **Severity:** high.
- **Fix:** одна явная строка в PRD: «W1-срез ускоряет V1/LLM/verification относительно roadmap vision (нед. 4-6/7-10), актуальный план - Jira PMM-3», с датой решения Mike.

### GAP-3. Фиксированный web UI v0 (GYR + счётчики, дайджест + critical) заменён новым механизмом без сверки
- **Vision:** раздел 4, «Продукт v0», строка Web UI - «GYR + счётчики сверху; дайджест + critical отдельно; Decision Inbox»; TL;DR - сигналы попадают в Daily Brief.
- **PRD:** Decision Inbox есть, но GYR, счётчики сверху, зоны «дайджест» и «critical», Daily Brief как фиксируемый 07-08 артефакт - не упомянуты ни разу. Вместо них вводится новая механика (Оценка 1-10, Ярусы алерт/расследование, порог), которая не выводится из решения vision и ему не сопоставлена.
- **Severity:** high.
- **Fix:** замапить Ярусы на зоны vision (Ярус расследования ~ critical, Ярус алерта ~ дайджест) и добавить GYR + счётчики в требования PA-38-шва; либо оформить supersede решения Web UI v0.

### GAP-4. MPStats-бенчмарки выпали из SCN-001 без explicit non-goal
- **Vision:** раздел 4 - «Методология SCN-001/002: декомпозиция U x CVR x AOV + бенчмарк MPStats "категория vs ты" (Lebesgue-паттерн) - в MetricAuthority v1»; строка Данные №35 - «MPStats-бенчмарки (аккаунт есть)».
- **PRD:** FR-8 содержит только декомпозицию против собственного baseline; MPStats и внешний бенчмарк не упомянуты и не помещены в Non-Goals (раздел 5). Ответ на вопрос «использует ли W1 SCN-001 бенчмарки» в PRD отсутствует.
- **Severity:** medium.
- **Fix:** либо добавить внешний бенчмарк как W1-шаг в FR-8, либо явную строку в Non-Goals: «MPStats-бенчмарк - W2, т.к. требует калибровки на живых данных».

### GAP-5. Per-client пороги из Client Passport не отражены в Policy Layer W1
- **Vision:** раздел 4, строка Сигналы - «пороги глобальные + per-client из Client Passport»; раздел 7 - «Client Passport + Decision Memory - контракты M2 без изменений».
- **PRD:** Decision Memory есть, Client Passport не упоминается вообще; FR-20 описывает правила с метаданными (включая «клиент»), но принцип «глобальные + per-client» не зафиксирован.
- **Severity:** medium.
- **Fix:** в FR-20 добавить «уровни применения: глобальный + per-client (Client Passport)» или зафиксировать допущение «W1 = только глобальные» с пометкой о Client Passport в W2.

### GAP-6. Цена/СПП daily (№34) не отражены
- **Vision:** раздел 4, строка Данные - «цена/СПП daily (№34)».
- **PRD:** отсутствуют. При этом AOV в FR-8 и ₽-оценки в FR-9/UJ-2 зависят от цены; источник цены в W1 не назван.
- **Severity:** medium.
- **Fix:** включить «цена/СПП daily из Statistics API» в раздел источников W1 (см. GAP-1).

### GAP-7. OQ-2 переоткрывает уже решённый в vision вопрос о складе/поставках
- **Vision:** раздел 4, строка W4 - «склад клиента руками AM (№38)» - источник вручную уже назначен решением интервью.
- **PRD:** OQ-2 предлагает кандидатов «ручной ввод AM, XLSX-импорт, WB API» без ссылки на №38, как будто решения не было.
- **Severity:** medium.
- **Fix:** закрыть OQ-2 со ссылкой «ручной ввод AM - согласно №38» либо явно supersede №38 с обоснованием.

### GAP-8. Недельная сводка Mike (№10) выпала
- **Vision:** раздел 4, строка Mike - «Недельная сводка портфеля + инциденты сразу (№10)».
- **PRD:** Telegram critical частично закрывает «инциденты сразу», но недельная сводка не упомянута ни в scope, ни в Non-Goals.
- **Severity:** medium.
- **Fix:** одна строка: в Non-Goals («недельная сводка Mike - после W1, один кабинет») или как FR-фоллоу-ап в PMM.

### GAP-9. Выходные per-client (№29) выпали из ритма
- **Vision:** раздел 4, строка Ритм - «выходные per-client (№6-7, №29)».
- **PRD:** FR-22 фиксирует 07:00/07-08 MSK, про выходные - тишина.
- **Severity:** medium.
- **Fix:** добавить в раздел 9 Assumptions: «W1, один кабинет - выходные по решению Mike (базово: цикл без выходных / пауза)» - до решения №29-логики.

### GAP-10. Метрика Signal recall / false positive отсутствует
- **Vision:** раздел 8, таблица метрик - «Signal recall / false positive; порог после baseline; critical errors = 0 всегда».
- **PRD:** раздел 7 - SM-C2 (объём сигналов не оптимизировать) не заменяет recall/FP; метрики качества детекции нет.
- **Severity:** medium.
- **Fix:** добавить SM: «recall/FP замеряется с первого прогона, порог - после baseline» (без порога в W1, как в vision).

### GAP-11. «Стоимость молчания» (№14) vs «деньги под риском за сутки» + UNKNOWN
- **Vision:** раздел 4, строка Сигналы - «₽-оценка "стоимость молчания" на каждом (№14)».
- **PRD:** FR-9 считает разницу факт-baseline за сутки (SCN-001); FR-4 допускает UNKNOWN по деньгам. Для SCN-008 ₽-оценка почти наверняка UNKNOWN - это расходится с «на каждом» и не оговорено.
- **Severity:** low.
- **Fix:** одна строка в FR-4/FR-6: «для SCN-008 ₽-оценка = UNKNOWN допустим, методология стоимость-молчания - W2».

### GAP-12. Персона «Кристина = AM» не следует из vision
- **Vision:** раздел 2 - Кристина названа только «domain review»; AM Proxima безымянный.
- **PRD:** разделы 1-2 - Кристина действует как AM, разбирающая инбокс.
- **Severity:** low.
- **Fix:** подтвердить у Mike, что Кристина и есть AM пилота; если нет - обезличить персону в PRD.
