## 1. Что это

**Одной строкой:** методичка структурированного интервью для найма менеджера Wildberries - скрипт на 90 минут, scorecard по 5 компетенциям, 37 вопросов с red/green flags и 7 (+5 встроенных) кейс-сценариев; цель - отличить реальный опыт от «заученного / GPT-ответа» («Core thesis: Real experience = specific details, trade-offs, failures, scenarios. Fake = generic answers, no depth», `memory/wb-manager-interview-system.md:14-16`).

- **Пользователь:** интервьюер / нанимающий менеджер («Для интерьююера», `templates/interview-script.md:3`; «Распечатай scorecard… Выбери 5-7 вопросов», `README.md:26-28`). Не селлер, не аккаунт-менеджер Proxima, не потребитель данных кабинета.
- **Триггер:** предстоящее собеседование («Quick Start (если интервью через час)», `README.md:46`). Пилот не выбран («Pilot location: TBD», `memory/wb-manager-interview-system.md:24`), статус «Research → MVP planning» (`:23`).
- **Дата:** создан `2026-06-07` (`memory/wb-manager-interview-system.md:6`); в дроп скопирован 30.08.2026 из `MILV/04-ai-business/tools/` (`../MANIFEST.md:3,34`) - каталог AI-бизнес-инструментов, не Proxima-проект; в git не отслеживается (`.orca/.gitignore:1`); mtime файлов 02.09.2026 04:46 - время копирования. «Шаблон основан на лучших практиках 2024-2025» (`templates/scorecard.md:130`).
- **Происхождение по признакам - LLM-генерация:** фрагменты на китайском внутри русского текста (`questions/04-logistics-questions.md:21`, `questions/05-buyouts-questions.md:31`), «Wildbacks» (`memory/MEMORY.md:5`, `memory/wb-manager-interview-system.md:22`), ни одной ссылки на документацию WB - все references про HR-методологию (`memory/wb-manager-interview-system.md:544-553`).

## 3. Доменные знания, пригодные для продукта

Оговорки перед таблицами:
- Ни одно правило не подкреплено ссылкой на документацию WB или данные - это **фольклорное знание автора**, оформленное как «что хочу услышать от кандидата». Перед посевом в детекторы - валидация менеджерами Proxima.
- Почти все числа - **условия сценариев** (синтетика), не пороги: «выкуп 12% / 38%», «маржа 45%», «5000 кликов / 10 продаж», «15 заказов за 2 часа», «10 одинозвёздных за день». Единственный порог, сформулированный как правило работы, - **«30+ дней» залёживания** (`questions/04-logistics-questions.md:15`, `scenarios/scenario-bank.md:84`).
- Ступени: M-04 = CAP-7 «отделяет сигнал от шума и ранжирует отклонения по деньгам в разрезе SKU и категории»; M-05 = CAP-8 «к каждой аномалии … гипотеза причины и что проверить, с источником каждой цифры» (`_bmad-output/specs/spec-wb-morning-brief/SPEC.md:46-51`).
- «Вычислимо сегодня» - относительно источников M-01/M-01b (`docs/state/API-FACTS.md`): заказы (с `isCancel`), продажи/возвраты (`saleID` S/R), цена (`priceWithDisc`, `discountPercent`, `spp`, `finishedPrice`), финотчёт v5 (`ppvz_sales_commission`, `delivery_rub`, `storage_fee`, `penalty`, `deduction`), остатки по складам (analytics `stocks-report`), воронка v3 (переходы → корзина → заказ → выкуп, конверсии) с 01.09 фоном. **Не собираются** (Non-goals / W2+ по PRD): отзывы и рейтинг, реклама (ставки, клики, ДРР), позиции в поиске, данные конкурентов, скорость доставки, данные покупателей.

Легенда: **Ф** = факт из текста (правило сформулировано автором), **И** = интерпретация (моё переложение в вычислимую форму или вывод).

### 4.3 Чек-лист «что проверить» (порядок исключения для CAP-8)

Синтез H-01, H-03, H-04, H-14. При падении продаж карточки проверять в порядке:
(1) остатки и разрез по складам → (2) собственная цена / скидка / СПП за последние N дней → (3) конверсия при стабильных переходах (карточка, цена) → (4) возвраты и отмены → (5) [нет данных] отзывы, рейтинг → (6) [нет данных] конкуренты, алгоритм, скорость доставки. Пункты 5-6 - в `unknowns` с формулировкой «что проверить вручную».

### 4.4 Принципы генерации действий для M-05 (из антипаттернов)

- Не предлагать снижение цены как действие по умолчанию (H-06); цена - после диагностики.
- Не предлагать «увеличить бюджет рекламы» при низкой конверсии (H-14).
- При обвале рейтинга / всплеске негатива первое действие - пауза рекламы (H-18).
- Решение по SKU с высоким возвратом - через деньги (маржа × объём), а не отключение (H-28); совпадает с CAP-7 «ранжирование по деньгам».
